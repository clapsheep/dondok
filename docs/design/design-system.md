# 돈독 디자인 시스템

## 브랜드 방향

돈독의 브랜드는 **영문 `dondok` 워드마크와 서로 연결된 `dd` 심볼**이다. 신혼부부의 따뜻함은 캐릭터나 분홍색 장식, 둥근 카드의 반복이 아니라 읽기 쉬운 밀도와 차분한 문장으로 표현한다. 금융 서비스의 신뢰를 잃지 않되 전문 투자 도구처럼 차갑게 보이지 않아야 한다.

원칙은 세 가지다.

1. 기록해야 할 행동이 장식보다 먼저 보인다.
2. 공동 사용은 사람을 구분하되 권한 차이처럼 표현하지 않는다.
3. 금액·날짜·상태는 색 없이도 읽히며 색은 보조 신호로만 쓴다.

## 로고

2026-10-09 사용자가 제공한 새 로고 자산을 사용한다. 소문자 `dondok` 워드마크와 서로 연결된 `dd` 모노그램은 제공된 SVG 윤곽을 그대로 유지한다. 브랜드 색상은 짙은 초록 `#19463C`와 연두 `#DBEE8B`다. 주요 행동의 초록색도 로고의 `#19463C`로 통일한다. 수입·지출·상태의 의미색은 유지한다.

- 원본 AI·SVG·PNG와 제작 설명: `design/brand/source/`
- 라이트 워드마크: `frontend/public/brand/dondok-wordmark.svg`
- 다크 워드마크: `frontend/public/brand/dondok-wordmark-dark.svg` — 같은 윤곽에 제공된 연두색만 적용
- 앱 아이콘·태블릿 rail·인증 화면 심볼: `frontend/public/brand/dondok-app-icon.svg`
- 파비콘: 같은 앱 아이콘 SVG와 32px PNG
- 홈 화면 설치: 192px·512px PNG, 별도의 512px maskable PNG, 180px Apple touch icon
- 로그인·가입·초대 전 화면과 데스크톱 상단 내비게이션은 SVG 워드마크를 사용한다. 태블릿의 좁은 rail은 앱 아이콘을 사용한다. 모바일 가계부 화면에 새 로고 header를 추가하지 않는다.
- 워드마크는 가로세로 비율을 유지하며 HTML 글자나 다른 폰트로 재현하지 않는다. 최소 표시 너비는 110px, rail 아이콘은 40px, favicon은 별도 32px PNG를 사용한다.
- 앱 아이콘은 라이트·다크에 같은 연두 배경과 짙은 초록 심볼을 사용한다. 다크 워드마크에는 CSS 밝기 필터를 적용하지 않는다.
- PWA의 `any`와 `maskable` 아이콘을 분리한다. Maskable·Apple용은 불투명 연두 배경 위에서 원본 심볼을 중심 기준 80%로 축소해 OS가 가장자리를 잘라도 심볼이 보존되도록 한다.
- 외부 SVG 이미지로 사용하고 장식용 이미지는 빈 `alt`를 둔다. 홈 링크의 접근 가능한 이름은 계속 `돈독 홈`이다. 생성한 SVG는 불필요한 편집기 metadata와 id를 제외한다.
- 재생성: E2E Chromium이 설치된 환경에서 `node design/brand/generate-assets.mjs`. 기존 Playwright를 사용하며 앱 production dependency를 추가하지 않는다. 원본 디자인은 수정하지 않는다.
- 생성 파일은 새 `/brand/` 경로로 제공하고 PWA 정적 앱 셸에 포함한다. API·금융 데이터 캐시 정책과 draft를 보존하는 업데이트 prompt는 유지한다.

실제 UI는 [`frontend/src/index.css`](../../frontend/src/index.css)의 의미 토큰을 사용하고 [`design/tokens.css`](../../design/tokens.css)는 디자인 참조로 동기화한다. D-074에 따라 hover·선택·보조문·구분선도 중립 회색을 사용한다. 황동색은 작은 본문이나 흰 배경 위 버튼 색으로 쓰지 않는다. 수입·지출·이체는 아이콘, 부호, 레이블을 색과 함께 제공한다. 멤버 색상은 사람 구분용이며 소유권이나 편집 권한을 의미하지 않는다.

구성원 avatar는 6개의 저채도 light/dark 조합 중 구성원 ID로 항상 같은 색을 고르고 표시명의 첫 grapheme을 fallback으로 사용한다. 목록 metadata는 20px, 일반 표시는 28px, 선택 option은 32px을 기본으로 하며 반드시 전체 이름과 함께 둔다. 현재 사용자는 `나` 표식을 함께 표시해 이니셜과 색에 의미를 맡기지 않는다.

통계 분류 차트는 `--chart-1`부터 `--chart-6`까지의 녹색·테라코타·청색·황동·자주·올리브 저채도 팔레트를 사용한다. 이 팔레트는 분류 식별용이라 수입·지출 의미색에 종속하지 않으며, 조각과 분류 행 표지는 같은 색을 사용한다. 색은 정확한 분류명·금액·비율을 보조할 뿐 대체하지 않는다.

연간 월별 막대그래프는 분류색이 아니라 `--income`과 `--expense` 의미색을 사용한다. 열두 달의 두 막대를 같은 척도로 비교하고, 연도·월·방향 label과 펼칠 수 있는 원 단위 월별 목록을 함께 제공해 색과 막대 높이만으로 값을 전달하지 않는다.

중립 테마의 검증 대비는 light 본문 17.93:1·보조문 5.50:1·입력 경계 3.31:1, dark 본문 17.18:1·보조문 6.61:1·입력 경계 4.52:1이다. 본문은 기본 배경, 보조문과 입력 경계는 표면을 기준으로 검증하며 색 변경 시 대비를 다시 확인한다.

기본 primary인 `forest-700`은 로고와 같은 `#19463C`, 버튼 hover인 `forest-800`은 `#143A32`다. 나머지 forest 단계도 같은 초록 계열로 맞춘다. 다크 모드는 채워진 주요 버튼의 초록색과 흰 글자를 유지하고, 텍스트·선택 테두리에 밝은 forest 단계를 사용한다. 다크 포커스는 `#80C7B7`로 대비를 확보한다.

Tailwind에서 사용하는 forest 단계는 theme token에 모두 정의해 생성되지 않는 dark class가 light 배경을 남기지 않게 한다. dark에서 텍스트·선택·hover·focus·아이콘·native date/select는 의미 token과 `color-scheme: dark`를 같이 사용하고, 로고는 밝기 filter 대신 연두색 워드마크와 제공된 앱 아이콘을 사용한다.

## 글꼴과 숫자

- 한국어 UI: Pretendard Variable, 대체로 `system-ui`, `sans-serif`
- 본문: 15–16px, 줄높이 1.5 이상
- 보조문: 13–14px, 12px 미만 금지
- 화면 제목: 24–28px, 과도한 굵기 사용 금지
- `홈 · 자산 · 통계 · 설정` 주요 메뉴의 대제목은 공통 `PageTitle`을 사용해 viewport와 관계없이 24px semibold를 유지한다. 화면마다 반응형 글자 크기를 따로 지정하지 않는다.
- 금액: `font-variant-numeric: tabular-nums`, 천 단위 구분, 원 단위
- `-12,000원`처럼 부호와 단위를 항상 제공하며 색만으로 수입·지출을 표현하지 않는다.

## 공간과 표면

4px 단위를 사용한다. 주요 간격은 8, 12, 16, 24, 32px이며 한 화면에서 다른 체계를 섞지 않는다. 입력 화면의 밀도는 실제 입력량에 비례해야 하며, 큰 빈 공간이나 반복 설명으로 단계가 더 많아 보이게 하지 않는다.

- 일반 입력은 데스크톱 40px·14px 글자, 터치 환경 44px·16px 글자로 제공한다. 라벨은 13px medium이다. 버튼 조작 영역은 기본 44px이고 금액 입력은 48px로 구분한다. compact 필터는 32px 표면과 44px 조작 영역을 분리한다.
- 연속된 폼 필드 간격은 12–16px, 섹션의 위아래 간격은 20–24px을 기본으로 한다. 구분선과 제목이 충분한 경우 여백을 추가 계층처럼 반복하지 않는다.
- 한 화면의 짧은 폼을 `기본 정보`, `소유`, `금액과 날짜`처럼 당연한 입력 묶음으로 다시 나누지 않는다. 필드 label만으로 흐름이 이해되면 하나의 연속된 form으로 두고, 시각적 섹션 제목은 조건부 전문 설정처럼 맥락 전환이 실제로 필요한 곳에만 사용한다.
- 모바일 거래 입력은 금액부터 내용까지 위에서 아래로 읽는 단일 열이다. 날짜·분류·자산처럼 서로 다른 입력을 단지 폭을 채우기 위해 같은 행에 놓지 않는다. iPad·데스크톱에서도 이체의 보내는 자산과 받는 자산처럼 사용자가 동시에 비교해야 하는 필드만 충분한 폭에서 같은 행에 배치하고, 다른 필드는 의미에 맞는 최대 폭의 독립 행으로 둔다.
- 거래 날짜는 금액과 같은 전체 폭·48px control로 두고 짧은 max-width를 적용하지 않는다. 공통 `DatePickerField`는 선택 날짜와 달력 icon을 trigger에서 함께 보여주며, 모바일 하단 drawer와 iPad·데스크톱 anchored popover 안에 같은 `Calendar` DOM을 재배치한다.
- 제품 페이지에는 공용 `Card` 컴포넌트나 섹션별 박스형 표면을 두지 않는다.
- 페이지와 필요한 섹션은 같은 배경 위에서 이어지며 제목·여백·정렬·1px 구분선으로 계층을 만든다. 모든 필드 묶음에 제목과 구분선을 반복하지 않는다.
- 입력·버튼 등 조작 컨트롤의 radius는 4~6px, 실제 overlay인 모달·시트·popover는 최대 8px다. 휴대폰 floating 하단 dock은 기기 모서리와 맞추기 위한 20~24px 외곽 radius를 예외로 허용한다.
- 공통 `DialogContent`는 기본 안쪽 여백 20px, `sm` 이상 24px을 제공한다. 내부 form이나 header·body·footer가 자체 여백을 관리하는 dialog는 `p-0 sm:p-0`으로 공통 여백을 해제해 중복을 피한다.
- 데이터 목록은 표·행·구분선과 금액 정렬을 우선한다. 메인 달력은 D-072에 따라 날짜 칸을 얇은 가로·세로 그리드로 구분한다. 요일 머리글과 바깥 테두리는 박스로 감싸지 않으며, 셀 내용은 위쪽 왼편에 정렬하고 숫자 주위 작은 원형 날짜 표식과 작은 금액·건수 행을 사용한다. 달력 전용 `--calendar-income`(빨강)·`--calendar-expense`(파랑)를 light/dark 모두 정의하며 다른 화면의 수입·지출 토큰은 유지한다.
- 자산 행은 자산 원장으로 drill-down하고, 설정은 원장 header 우상단의 44px 기어 아이콘으로 분리한다. 기어는 `자산 편집` 접근 가능한 이름을 가지며 장식용 원형 배경이나 별도 설정 카드를 만들지 않는다.
- 홈 일별보기·자산 원장은 공통 `TransactionDateGroup`의 12px normal 날짜 제목과 건수를 사용한다(D-073). `TransactionList`는 왼쪽 12px/16px 들여쓰기와 행 사이 4px 여백, `TransactionListRow`는 최소 64px 높이와 위아래 12px 패딩으로 내용·흐름과 우측 금액을 정렬한다. 날짜는 평일 회색·토요일 파란색·일요일 빨간색으로 낮은 위계의 구분점 역할을 하며 굵게 강조하지 않는다. 거래 행에는 구분선을 반복하지 않는다. 홈 일별 날짜 머리글에는 옅은 선 한 개와 불투명 배경을 두고 날짜 section 안에서 `position: sticky; top: 0`으로 유지한다. 날짜 그룹 사이 margin을 없애 다음 머리글이 이전 머리글을 끊김 없이 밀어내게 한다. 달력 날짜 상세도 동일 목록·행 컴포넌트를 사용한다.
- 거래 행은 상세로 drill-down한 뒤 일반 거래만 본문 아래 `기록 편집`·`기록 삭제`를 제공한다. 목록 행 전체를 편집 버튼처럼 이름 붙이지 않고 접근 가능한 이름에도 `거래 상세`를 사용한다.
- 그림자는 dialog, sheet, popover, toast, PWA 갱신 prompt와 휴대폰 floating 하단 dock처럼 실제로 떠 있는 표면에만 한 단계 사용한다.
- 빈 상태와 오류 상태는 해당 영역의 인라인 문구와 행동으로 두며 별도 박스로 감싸지 않는다.
- 화면당 주요 행동은 하나만 채워진 primary 버튼으로 둔다.
- 그라데이션, glassmorphism, 과도한 일러스트와 반복 애니메이션은 사용하지 않는다.

## 컴포넌트 상태

모든 입력과 행동 컴포넌트는 default, hover, focus-visible, disabled, loading, error 상태를 정의한다. 데이터 화면에는 loading, skeleton, empty, error, offline, reconnecting 상태가 필요하다. 동시 수정 충돌은 사용자의 입력을 지우지 않고 최신 데이터 확인과 다시 적용 행동을 제공한다.

## 접근성 승인 기준

- 본문 대비 WCAG AA 4.5:1 이상, 큰 글자와 비텍스트 UI 3:1 이상
- 키보드 focus ring을 제거하지 않는다.
- 터치 목표 44×44px 이상, touch·keyboard·trackpad에서 같은 핵심 행동 제공
- 모든 아이콘 버튼에 접근 가능한 이름 제공
- 오류는 필드 옆 설명과 상단 요약을 함께 제공
- 200% 확대와 320px 너비에서 가로 스크롤 없이 핵심 작업 가능
- 모바일·태블릿의 네 방향 safe area와 동적 viewport에서 내비게이션·저장 행동·오류가 가려지지 않음
- `prefers-reduced-motion`에서 이동성 애니메이션 제거

## 변경 관리

토큰은 직접 화면별로 복제하지 않는다. 새로운 색·간격·컴포넌트 변형은 UX/UI와 Frontend가 의미와 재사용 범위를 합의한 뒤 공통 토큰 또는 shadcn variant로 추가한다.

자산과 연결 계좌 선택은 Base UI Popover 기반 공통 `AssetPicker`를 사용한다. 모바일은 safe area 위의 bottom drawer, iPad·데스크톱은 trigger에 붙는 popover로 같은 DOM을 재배치한다. 모바일 drawer는 종류 필터 결과의 개수와 무관하게 동적 viewport 기준의 일정한 외곽 높이와 위쪽 위치를 유지하고 목록만 내부 스크롤한다. trigger와 option에는 자산 종류 icon, 이름, 종류, 소유자 avatar/marker와 잔액을 함께 두고, 여러 종류가 섞이면 줄바꿈하지 않는 compact 종류 필터를 제공한다. trigger는 48px 안팎, option은 이름·금액과 종류·소유자를 두 줄에 정돈한 52~56px 구분선 행으로 유지하며 큰 카드처럼 만들지 않는다. overlay 헤더 우상단에는 compact `모든 자산 보기` switch를 두고 기본은 꺼서 로그인 구성원의 개인 자산만 보여 주며, 켜면 다른 구성원 자산을 같은 목록에 더한다. 제목·switch·닫기 버튼은 320px에서도 겹치거나 가로 overflow를 만들지 않고, overlay radius는 8px을 넘기지 않는다.

데스크톱 내비게이션은 64px 높이의 고정 상단 바다. 28px 워드마크와 텍스트 메뉴 네 개를 왼쪽부터 배치하고 설정은 오른쪽 끝에 둔다. 기본 항목은 medium 보조색, hover는 중립 hover 표면과 진한 글자, active는 semibold primary 글자와 2px 밑줄을 사용한다. 다크에서는 밝은 forest 글자와 밑줄로 대비를 유지한다. 768–1279px은 같은 DOM을 80px 아이콘 rail로 배치하며 leading indicator를 사용한다.

내비게이션의 현재 위치는 배경색만으로 표시하지 않는다. primary 표시선(데스크톱 밑줄·태블릿 leading indicator), 굵기 변화, 텍스트 또는 아이콘 상태와 `aria-current="page"`를 함께 사용한다.

### 공통 입력 표면

Input·NativeSelect·Textarea·날짜·금액 필드는 controlStyles와 control-border 토큰을 공유한다. 배경은 페이지 배경색, 라이트 테두리는 #D4D4D4, 다크는 #404040이며 hover에서 조금 선명해진다. 포커스는 브랜드색 경계와 2px 저채도 ring으로 표시하고 오류·disabled·키보드 조작을 유지한다. 필터는 종류·구성원·기간·초기화만 한 줄에 두고 종류·구성원은 즉시 적용한다. 날짜는 페이지를 가리지 않는 작은 비모달 popover에서 선택하며 넓은 날짜 입력 두 칸을 도구 줄에 상시 표시하지 않는다.
