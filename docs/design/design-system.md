# 돈독 디자인 시스템

## 브랜드 방향

돈독의 인상은 **둘의 돈이 머무는 단정한 항아리**다. 신혼부부의 따뜻함은 캐릭터나 분홍색 장식, 둥근 카드의 반복이 아니라 읽기 쉬운 밀도와 차분한 문장으로 표현한다. 금융 서비스의 신뢰를 잃지 않되 전문 투자 도구처럼 차갑게 보이지 않아야 한다.

원칙은 세 가지다.

1. 기록해야 할 행동이 장식보다 먼저 보인다.
2. 공동 사용은 사람을 구분하되 권한 차이처럼 표현하지 않는다.
3. 금액·날짜·상태는 색 없이도 읽히며 색은 보조 신호로만 쓴다.

## 로고

로고마크는 뚜껑과 몸통만 남긴 항아리다. 황동색 뚜껑은 모으는 행위를, 짙은 녹색 몸통은 안정적으로 보관한다는 의미를 가진다.

- 기본 조합형: `design/brand/dondok-logo-ko.svg`
- 어두운 배경용: `design/brand/dondok-logo-ko-reverse.svg`
- 어두운 rail용 마크: `design/brand/dondok-mark-reverse.svg`
- 정사각형 마크: `design/brand/dondok-mark.svg`
- 브라우저 파비콘: `design/brand/favicon.svg`
- 최소 크기: 마크 24px, 파비콘 전용 도형 16px, 조합형 너비 110px
- 안전 여백: 마크 몸통 너비의 25% 이상
- 아이보리 또는 흰 배경을 기본으로 사용한다.
- 기울이기, 윤곽선 추가, 임의 그라데이션, 그림자, 항아리 안에 통화 기호 삽입을 금지한다.
- 앱에서는 마크 SVG와 HTML 텍스트 워드마크 조합을 우선해 글꼴 로딩과 접근성을 제어한다. 조합형 SVG는 문서·미리보기 용도이며, 배포 채널용 고정 자산은 확정 폰트로 outline한다.
- 같은 문서에 여러 SVG를 inline할 수 있도록 내부 `id`를 사용하지 않는다. 외부 이미지에는 `alt`, 장식용 inline SVG에는 `aria-hidden="true"`를 적용한다.
- dark sidebar와 80px icon rail에서는 reverse mark만 사용한다. 기본 녹색 mark를 dark surface에 직접 올리지 않는다.

## 색상

| 역할 | 기준색 | 사용 |
|---|---|---|
| Deep Green | `#174B3A` | 로고, 주요 버튼, 선택 상태 |
| Warm Ivory | `#F8F5ED` | 기본 배경, 따뜻한 표면 |
| Muted Brass | `#B8893B` | 작은 브랜드 포인트와 강조선 |
| Ink Green | `#173F33` | 본문과 금액 |
| Terracotta | `#B6503E` | 지출과 위험 상태 보조색 |

실제 UI는 [`design/tokens.css`](../../design/tokens.css)의 의미 토큰을 사용한다. 황동색은 작은 본문이나 흰 배경 위 버튼 색으로 쓰지 않는다. 수입·지출·이체는 아이콘, 부호, 레이블을 색과 함께 제공한다. 멤버 색상은 사람 구분용이며 소유권이나 편집 권한을 의미하지 않는다.

구성원 avatar는 6개의 저채도 light/dark 조합 중 구성원 ID로 항상 같은 색을 고르고 표시명의 첫 grapheme을 fallback으로 사용한다. 목록 metadata는 20px, 일반 표시는 28px, 선택 option은 32px을 기본으로 하며 반드시 전체 이름과 함께 둔다. 현재 사용자 `나`와 공동 소유는 별도 문구·공동 icon으로 표시해 이니셜과 색에 의미를 맡기지 않는다.

통계 분류 차트는 `--chart-1`부터 `--chart-6`까지의 녹색·테라코타·청색·황동·자주·올리브 저채도 팔레트를 사용한다. 이 팔레트는 분류 식별용이라 수입·지출 의미색에 종속하지 않으며, 조각과 분류 행 표지는 같은 색을 사용한다. 색은 정확한 분류명·금액·비율을 보조할 뿐 대체하지 않는다.

연간 월별 막대그래프는 분류색이 아니라 `--income`과 `--expense` 의미색을 사용한다. 열두 달의 두 막대를 같은 척도로 비교하고, 연도·월·방향 label과 펼칠 수 있는 원 단위 월별 목록을 함께 제공해 색과 막대 높이만으로 값을 전달하지 않는다.

검증 기준 대비는 light의 primary 9.16:1, 본문 10.74:1, 지출 5.55:1, 입력 경계 3.68:1이며 dark의 지출 6.75:1, 수입 9.00:1, 이체 8.69:1, 입력 경계 4.88:1이다. 색 변경 PR은 같은 조합의 대비 검증 결과를 포함한다.

Tailwind에서 사용하는 forest 단계는 theme token에 모두 정의해 생성되지 않는 dark class가 light 배경을 남기지 않게 한다. dark에서 텍스트·선택·hover·focus·아이콘·native date/select는 의미 token과 `color-scheme: dark`를 같이 사용하고, 로고는 밝기 filter 대신 reverse mark와 워드마크를 사용한다.

## 글꼴과 숫자

- 한국어 UI: Pretendard Variable, 대체로 `system-ui`, `sans-serif`
- 본문: 15–16px, 줄높이 1.5 이상
- 보조문: 13–14px, 12px 미만 금지
- 화면 제목: 24–28px, 과도한 굵기 사용 금지
- `홈 · 자산 · 통계 · 설정` 주요 메뉴의 대제목은 공통 `PageTitle`을 사용해 viewport와 관계없이 24px semibold를 유지한다. 화면마다 반응형 글자 크기를 따로 지정하지 않는다.
- 금액: `font-variant-numeric: tabular-nums`, 천 단위 구분, 원 단위
- `-12,000원`처럼 부호와 단위를 항상 제공하며 색만으로 수입·지출을 표현하지 않는다.

## 공간과 표면

4px 단위를 사용한다. 주요 간격은 8, 12, 16, 24, 32px이며 한 화면에서 다른 체계를 섞지 않는다. 입력 화면의 밀도는 실제 입력량에 비례해야 하며, 큰 빈 공간이나 반복 설명으로 단계가 더 많아 보이게 하지 않는다.

- 입력·버튼의 기본 높이는 44px로 두고, 핵심 행동을 특별히 강조할 때만 48px를 사용한다. 모든 모바일 터치 목표는 최소 44×44px다.
- 연속된 폼 필드 간격은 12–16px, 섹션의 위아래 간격은 20–24px을 기본으로 한다. 구분선과 제목이 충분한 경우 여백을 추가 계층처럼 반복하지 않는다.
- 한 화면의 짧은 폼을 `기본 정보`, `소유`, `금액과 날짜`처럼 당연한 입력 묶음으로 다시 나누지 않는다. 필드 label만으로 흐름이 이해되면 하나의 연속된 form으로 두고, 시각적 섹션 제목은 조건부 전문 설정처럼 맥락 전환이 실제로 필요한 곳에만 사용한다.
- 모바일 거래 입력은 금액부터 내용까지 위에서 아래로 읽는 단일 열이다. 날짜·분류·자산처럼 서로 다른 입력을 단지 폭을 채우기 위해 같은 행에 놓지 않는다. iPad·데스크톱에서도 이체의 보내는 계좌와 받는 계좌처럼 사용자가 동시에 비교해야 하는 필드만 충분한 폭에서 같은 행에 배치하고, 다른 필드는 의미에 맞는 최대 폭의 독립 행으로 둔다.
- 거래 날짜는 금액과 같은 전체 폭·48px control로 두고 짧은 max-width를 적용하지 않는다. 공통 `DatePickerField`는 선택 날짜와 달력 icon을 trigger에서 함께 보여주며, 모바일 하단 drawer와 iPad·데스크톱 anchored popover 안에 같은 `Calendar` DOM을 재배치한다.
- 제품 페이지에는 공용 `Card` 컴포넌트나 섹션별 박스형 표면을 두지 않는다.
- 페이지와 필요한 섹션은 같은 배경 위에서 이어지며 제목·여백·정렬·1px 구분선으로 계층을 만든다. 모든 필드 묶음에 제목과 구분선을 반복하지 않는다.
- 입력·버튼 등 조작 컨트롤의 radius는 4~6px, 실제 overlay인 모달·시트·popover는 최대 8px다. 휴대폰 floating 하단 dock은 기기 모서리와 맞추기 위한 20~24px 외곽 radius를 예외로 허용한다.
- 데이터 목록과 달력은 표·행·구분선과 금액 정렬을 우선한다.
- 그림자는 dialog, sheet, popover, toast, PWA 갱신 prompt와 휴대폰 floating 하단 dock처럼 실제로 떠 있는 표면에만 한 단계 사용한다.
- 빈 상태와 오류 상태는 해당 영역의 인라인 문구와 행동으로 두며 별도 박스로 감싸지 않는다.
- 화면당 주요 행동은 하나만 채워진 primary 버튼으로 둔다.
- 그라데이션, glassmorphism, 과도한 일러스트와 반복 애니메이션은 사용하지 않는다.

## 컴포넌트 상태

모든 입력과 행동 컴포넌트는 default, hover, focus-visible, disabled, loading, error 상태를 정의한다. 데이터 화면에는 loading, skeleton, empty, error, offline, reconnecting 상태가 필요하다. 동시 수정 충돌은 사용자의 입력을 지우지 않고 최신 데이터 확인과 다시 적용 행동을 제공한다.

## 접근성 승인 기준

- 본문 대비 WCAG AA 4.5:1 이상, 큰 글자와 비텍스트 UI 3:1 이상
- 키보드 focus ring을 제거하지 않는다.
- 터치 목표 44×44px 이상, touch·keyboard·trackpad에서 같은 핵심 행동 제공
- 모든 아이콘 버튼에 접근 가능한 이름 제공
- 오류는 필드 옆 설명과 상단 요약을 함께 제공
- 200% 확대와 320px 너비에서 가로 스크롤 없이 핵심 작업 가능
- 모바일·태블릿의 네 방향 safe area와 동적 viewport에서 내비게이션·저장 행동·오류가 가려지지 않음
- `prefers-reduced-motion`에서 이동성 애니메이션 제거

## 변경 관리

토큰은 직접 화면별로 복제하지 않는다. 새로운 색·간격·컴포넌트 변형은 UX/UI와 Frontend가 의미와 재사용 범위를 합의한 뒤 공통 토큰 또는 shadcn variant로 추가한다.

자산과 연결 계좌 선택은 Base UI Popover 기반 공통 `AssetPicker`를 사용한다. 모바일은 safe area 위의 bottom drawer, iPad·데스크톱은 trigger에 붙는 popover로 같은 DOM을 재배치한다. 모바일 drawer는 종류 필터 결과의 개수와 무관하게 동적 viewport 기준의 일정한 외곽 높이와 위쪽 위치를 유지하고 목록만 내부 스크롤한다. trigger와 option에는 자산 종류 icon, 이름, 종류, 소유자 avatar/marker와 잔액을 함께 두고, 여러 종류가 섞이면 줄바꿈하지 않는 compact 종류 필터를 제공한다. trigger는 48px 안팎, option은 이름·금액과 종류·소유자를 두 줄에 정돈한 52~56px 구분선 행으로 유지하며 큰 카드처럼 만들지 않는다. overlay radius는 8px을 넘기지 않는다.

내비게이션의 현재 위치는 배경색만으로 표시하지 않는다. primary leading indicator, 굵기 변화, 텍스트 또는 아이콘 상태와 `aria-current="page"`를 함께 사용한다.
