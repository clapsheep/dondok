# 돈독 UX 가이드

## 제품 경험

돈독은 회계 지식 없이도 둘 이상의 구성원이 같은 장부를 안심하고 기록하는 서비스다. 기본값은 가장 흔한 행동을 빠르게 만들고, 카드 정산처럼 복잡한 규칙은 필요할 때만 단계적으로 보여준다.

## 모바일 우선 정보 구조

하단 내비게이션은 `홈 · 기록 · 자산 · 통계` 네 항목을 기본으로 한다. 기록은 독립된 탭이지만 크기나 애니메이션으로 과장하지 않는다. 홈 자체가 공동 가계부이며 월간 달력과 일별 원장을 보기 전환으로 제공한다. 멤버·카테고리·자산 필터는 공동 전체 기본값 위에 선택적으로 노출하고, 가계부와 구성원 설정은 상단 프로필 메뉴에 둔다.

데스크톱에서는 같은 항목을 왼쪽 내비게이션으로 옮기고 콘텐츠 최대 너비를 제한한다. 정보 구조와 명칭은 화면 크기에 따라 바꾸지 않는다.

기능을 단계적으로 공개하는 개발 단계에서는 아직 동작하지 않는 메뉴를 비활성 자리로 노출하지 않는다. 거래 단계는 `홈 · 기록 · 자산 · 설정`만 모바일 하단 탭, iPad 아이콘 rail, 데스크톱 sidebar에 같은 순서로 제공한다. 통계가 구현되면 최종 네 핵심 메뉴를 `홈 · 기록 · 자산 · 통계`로 바꾸고 설정은 같은 변경에서 접근 가능한 상단 프로필·utility 영역으로 이동해 핵심 메뉴에 중복해 남기지 않는다.

## 카드 없는 페이지 구성

제품 페이지는 반복되는 카드 컨테이너로 정보를 나누지 않는다. 한 화면 안의 섹션은 같은 배경 위에서 이어지고, 의미 있는 제목·일관된 간격·열 정렬·얇은 가로 구분선으로 구분한다. 폼은 하나의 연속된 `form` 안에서 `fieldset`과 `legend`를 사용하며, 조건부 필드도 기존 흐름 아래에 인라인으로 펼친다. 섹션마다 배경·네 방향 테두리·radius·그림자를 함께 주거나 표면을 중첩하지 않는다.

입력과 버튼의 테두리, 선택 상태와 focus ring은 조작 가능성을 알리는 컨트롤 표현이므로 이 원칙의 예외가 아니다. 별도 표면과 그림자는 dialog, sheet, popover, toast, PWA 갱신 prompt처럼 현재 페이지 위에 실제로 떠야 하는 요소에만 허용한다. 빈 상태·오류·한도 도달 안내는 해당 목록이나 폼 영역 안에 문구와 행동을 바로 배치한다.

## 홈 가계부

참여한 사용자의 홈은 구성원 소개나 장식성 대시보드가 아니라 실제 공동 원장이다. 헤더에는 현재 월, 이전·다음 월, `월별/일별` 전환과 `기록` 행동만 둔다. 구성원 수와 초대 행동은 설정으로 이동한다.

- 월별 보기는 하나의 7열 달력 표를 사용한다. 각 날짜 셀에 수입은 녹색 `+금액`, 지출은 빨간색 `-금액`으로 표시하며 부호·색·정렬을 함께 사용한다.
- 오늘과 선택일은 배경 카드가 아니라 얇은 외곽선·밑줄·굵기 차이로 구분한다.
- 모바일에서도 날짜마다 둥근 카드를 반복하지 않고 full-bleed 달력 grid와 구분선을 유지한다. 금액은 공간에 맞춰 축약하되 접근 가능한 이름에는 원 단위 전체 값을 제공한다.
- 일별 보기는 날짜 제목과 그날의 수입·지출 합계 아래에 거래 행을 연속 배치한다. 행은 내용, 분류·자산·주체, 우측 정렬 금액 순이며 cursor pagination으로 필요한 범위만 추가한다.
- 월 합계가 필요하면 카드 세 개로 나누지 않고 달력 위 한 줄에 `수입 · 지출 · 순액`을 정렬해 표시한다.
- 데이터가 없을 때도 큰 일러스트나 온보딩 카드를 만들지 않고 달력을 그대로 보여주며 `아직 기록이 없습니다`와 기록 행동만 제공한다.

## 공동 월간 통계

통계 첫 진입은 `Asia/Seoul`의 이번 달과 필터 없는 `공동 전체`다. 헤더는 `통계`, 이전 달, `YYYY년 M월`, 다음 달, `공동 전체 · 필터`, `최신값 확인` 순서로 두고, 현재 달이 아닐 때만 `이번 달` 복귀 행동을 낮은 위계로 제공한다. 월과 적용된 필터, 분류 비중 방향은 `/statistics` search parameter를 source of truth로 삼아 새로고침·뒤로 가기·PWA 재실행·viewport 변경에도 유지한다.

월 요약은 구조적 카드 세 개가 아니라 전체 폭의 얇은 위·아래 구분선 사이에 `수입 · 지출 · 순액` 순서의 하나의 `dl`로 둔다. 수입과 지출은 같은 크기, 순액은 한 단계 큰 금액으로 표현한다. 표시 부호는 수입 `+income`, 지출 `-expense`, 순액 `income-expense`로 계산해 환불로 월 지출 순금액이 음수가 되면 지출 표시가 `+금액`이 되도록 한다. 수입·지출·순액 label과 부호를 항상 함께 보여주고 0원은 중립색으로 두어 녹색·빨간색만으로 의미를 전달하지 않는다. 금액은 원 단위 전체값, 우측 정렬, `tabular-nums`, 중간 줄바꿈 금지를 유지한다.

필터 trigger는 아무 조건이 없으면 `공동 전체`, 적용 후에는 선택한 값을 짧게 나열하고 `필터 2개`처럼 개수를 함께 알린다. 하나의 responsive filter panel/dialog 안에 `거래 주체`, `자산 소유자`, `분류` 세 `fieldset`을 두고 각 그룹은 `전체`를 포함한 단일 선택 radio로 구현한다. 거래 주체는 작성자가 아니라 실제 경제활동 주체, 자산 소유자는 거래의 주 자산에 붙은 현재 소유 marker임을 label로 구분하고 분류 선택지는 `식비 · 지출`처럼 방향을 함께 표시한다. 그룹 안에서는 한 값만 선택하고 선택된 서로 다른 그룹은 AND로 적용한다. panel draft는 `적용` 전까지 결과를 바꾸지 않으며 `초기화`는 세 그룹을 모두 `전체`로 되돌린다.

filter panel/dialog는 viewport별 별도 컴포넌트나 중복 DOM을 만들지 않는다. 동일한 form·focus 범위·draft를 모바일에서는 하단 안전 영역을 반영한 sheet 형태, iPad·데스크톱에서는 폭이 제한된 panel/dialog 형태로 CSS 재배치한다. 열고 닫기, 회전과 breakpoint 통과에서 선택 draft를 유지하고 닫으면 trigger focus를 복원한다. `Escape`와 브라우저 뒤로 가기는 먼저 panel만 닫는다. trigger는 `aria-expanded`와 연결된 panel 이름을 제공하고, 적용 뒤 결과 범위 변경을 `aria-live="polite"`로 한 번 알린다.

요약 다음은 `분류 비중`, `YYYY년 월별 합계` 순서다. 분류 비중은 `지출 · 수입` text subnav를 두고 지출을 기본으로 한다. 선택은 투명한 배경과 하단선, `aria-pressed`, 글자색·굵기로 표현하며 둥근 segmented control을 만들지 않는다. 정상적인 양수 합계와 양수 분류만 있을 때 production chart dependency 없는 compact native SVG 원형 차트를 먼저 보여준다. 원형 차트는 최대 6개 조각으로, 분류가 6개 이하면 모두 표시하고 7개 이상이면 순금액 상위 5개와 나머지 합계 `기타 N개`를 표시한다. 수입·지출의 한 색 계열에 묶지 않고 녹색·테라코타·청색·황동·자주·올리브의 서로 구별되는 저채도 팔레트를 같은 순서로 사용한다. 불투명도 차이만으로 조각을 구분하거나 고채도 무지개색·별도 장식 표면·animation을 만들지 않는다. 원형 차트는 보조 시각화이며 접근 가능한 이름을 제공한다.

정확한 값은 순금액 내림차순의 `분류명 | signed 금액 | 비율` 행과 그 아래 4px 수평 막대로 항상 함께 표시한다. 원형 차트 조각과 연결되는 작은 색 표지를 행에 두되 label·금액·비율을 대체하지 않는다. 상위 6개를 먼저 보여주며 더 있으면 `전체 N개 보기`로 같은 목록을 펼친다. 정상적인 양수 합계와 양수 분류만 있을 때 비율은 `분류 순금액 / 선택 방향 전체 순금액`의 소수점 한 자리다.

환불 때문에 선택 방향 전체 순금액이 0 이하라면 해당 방향의 모든 비율·원형 차트·막대를 숨기고 signed 금액 행만 유지한다. 전체 합계는 양수여도 하나 이상의 분류 순금액이 0 이하이면 양수 항목만의 비율이 전체를 왜곡하므로 방향 전체의 비율·원형 차트·막대를 함께 숨긴다. 이 상태에는 `환불을 반영해 비율 대신 분류별 순금액을 보여드려요`를 한 번 안내하며 음수 분류를 오류색이나 실패 상태로 표현하지 않는다.

연간 흐름은 선택 월이 속한 연도의 1월부터 12월까지 수입·지출을 나란히 둔 grouped bar graph로 표현한다. 두 막대는 기존 수입·지출 의미색과 문구 범례를 함께 사용하고, 높이는 해당 연도의 월별 수입·지출 순금액 절댓값 중 최댓값을 기준으로 비교한다. 환불 때문에 순금액의 방향이 바뀌어도 정확한 signed 값은 `월별 금액 목록`에서 유지한다. 선택 중인 달은 월 label의 굵기·색으로 구분하며 배경 카드로 강조하지 않는다. 모바일에서도 12개월 label과 두 막대를 한 화면 폭에 유지하고 chart 내부·페이지 가로 스크롤, animation, 별도 chart dependency를 만들지 않는다. 정확한 값은 hover `title`에만 의존하지 않고 바로 아래 펼칠 수 있는 12개 월 `ol`과 월별 `수입 · 지출` `dl`로 제공한다.

320~767px에서는 월 선택과 필터 행동을 자연스럽게 두 줄로 감싸고 요약을 `수입·지출` 두 열과 전체 폭 `순액`의 다음 행으로 둔다. 분류 비중 다음 연간 월별 합계를 한 열로 이어간다. iPad 세로는 요약 세 값을 한 행에 두되 분석 두 섹션은 차트 폭을 위해 한 열로 유지한다. iPad 가로·데스크톱은 같은 DOM을 `분류 비중 minmax(18rem, 2fr) | 연간 월별 합계 minmax(0, 3fr)` 두 열로 바꾸고 중간의 얇은 세로 구분선만 추가한다. iPad 분할 화면과 200% 확대에서 가용 폭이 줄면 container query로 다시 한 열이 되며 state와 focus를 초기화하지 않는다.

처음 조회와 새 월·필터 적용은 결과 영역 높이를 크게 바꾸지 않는 금액·행 skeleton을 사용하고, 같은 query의 background refetch는 기존 값을 가리지 않은 채 `최신값 확인 중`만 알린다. 이전 조건의 값을 새 조건 label 아래에 그대로 보여주지 않는다. 기록이 전혀 없는 월은 0원 요약과 `이번 달 수입·지출 기록이 없습니다`·`기록하기`를, 적용 필터 결과가 없으면 `선택한 조건에 맞는 기록이 없습니다`·`필터 초기화`를 보여준다. 선택 월이 비어도 같은 연도의 다른 달 기록이 있으면 연간 막대는 유지하고, 연도 전체가 비면 `YYYY년에는 수입·지출 기록이 없습니다`를 표시한다. 한 방향만 비면 해당 분류 영역에만 `이번 달 지출이 없습니다` 또는 `이번 달 수입이 없습니다`를 표시하고 다른 방향과 연간 막대는 유지한다. 첫 조회 실패는 같은 영역의 재시도, background refetch 실패는 기존 결과와 인라인 최신값 재시도를 제공한다. 오프라인에서는 마지막으로 앱 메모리에 남은 결과가 있으면 조회 시점과 갱신 불가를 알리고 금융 데이터를 service worker에 저장하지 않는다.

통계 요약은 `dl`, 분류 행은 실제 text와 signed 원화값, 연간 대체 목록은 월별 `time`과 `dl`을 사용한다. 원형 차트와 연간 막대그래프에는 방향·연도를 포함한 접근 가능한 이름을 제공하고 세부 수치 탐색은 바로 이어지는 실제 행이 담당한다. 월 이동, filter trigger·radio·적용·초기화, 분류 방향, 목록 펼치기의 hit area는 44px 이상이다. 긴 구성원·분류명은 시각적으로 말줄임해도 접근 가능한 이름과 filter panel에 전체를 남긴다. `320×568`, `390×844`, `768×1024`, `1180×820`, 200% 확대에서 원 단위 금액 중간 줄바꿈, 전체 페이지 가로 overflow, chart label 겹침, filter·focus 유실이 없어야 한다.

## 핵심 흐름

경제활동일·등록일처럼 `DATE`를 입력하는 모든 필드는 브라우저의 네이티브 `date` 컨트롤을 사용한다. 사용자가 입력 영역 어디를 클릭해도 기기와 브라우저에 맞는 달력 선택 UI를 열고, 키보드와 직접 입력도 그대로 지원한다. 달력 UI 지원 여부와 관계없이 서버에 전달하는 값은 기존 `YYYY-MM-DD` 계약을 유지한다.

### 가입과 연결

가입 후 아직 참여한 가계부가 없다면 `초대 코드를 받으셨나요?`를 먼저 묻고 다음 두 행동만 보여준다.

- 받지 않은 사용자는 `바로 시작하기`로 이름 입력 없이 새 가계부를 생성
- 받은 사용자는 `초대 코드 입력하기`로 이동해 숫자 6자리 입력

첫 화면에 코드 입력란을 함께 펼치지 않는다. 링크로 들어온 사용자는 별도 입력 없이 초대 미리보기를 보고, 직접 참여 화면에서는 모바일 숫자 키패드·6자리 길이 제한·가운데 정렬된 tabular 숫자로 짧은 코드를 입력한다. 참여 완료 후 홈으로 진입한다.

가입은 로그인 아이디, 이름, 이메일, 비밀번호를 받는다. 로그인 아이디는 상대 검색에 사용하지 않으며 공개 핸들·사용자 검색도 제공하지 않는다. 숫자 6자리 직접 입력 코드와 별도 초대 URL은 인증 식별자와 분리되어 있음을 문구로 설명한다.

한 사용자는 하나의 가계부에만 참여한다. 초대 수락 성공 즉시 홈으로 이동하고 초대 화면은 종료한다. 이미 참여한 사용자가 초대 URL을 다시 열면 확인 화면을 보여주지 않고 홈으로 이동한다. 가계부 설정에서 새 멤버 초대와 여러 발신 초대의 `사용 가능 · 만료 · 사용 완료` 상태를 관리하며, 초대 대기 상태가 홈 진입을 막거나 N명 가계부 전체를 2인 연결 대기 화면으로 되돌리지 않는다. 개인 나가기 UI는 제공하지 않는다.

가계부 생성은 이름 입력 없이 `바로 시작하기` 한 번으로 완료한다. 참여 후 공동 공간은 고정 화면 제목으로 안내하고, 이름 변경이나 가계부 전환 UI를 만들지 않는다. 초대 미리보기에서는 가계부 이름 대신 현재 구성원을 보여줘 사용자가 참여 대상을 확인하게 한다.

### 거래 기록

첫 화면에서 수입·지출·이체를 선택하고 금액에 초점을 둔다. 날짜와 실제 구성원은 오늘·본인을 기본값으로 한다. 사람 선택은 `거래 주체`나 `거래한 구성원` 대신 수입 `누가 받았나요?`, 지출 `누가 썼나요?`, 이체 `누가 옮겼나요?`로 묻고 상세에서는 각각 `받은 사람`, `쓴 사람`, `옮긴 사람`으로 표시한다. 다른 멤버 선택 시 프로필 표시와 이름을 함께 보여준다. 작성자는 인증 세션에서 자동 기록하므로 입력 항목으로 노출하지 않는다.

선택한 사람은 해당 수입·지출·이체를 실제로 한 구성원 한 명이다. 공동 선택은 제공하지 않는다. 다른 구성원을 선택해도 현재 로그인한 사용자는 작성자로 별도 기록된다는 점은 상세 화면에서만 보조 정보로 보여주고 입력 흐름을 복잡하게 만들지 않는다.

수입·지출의 필수 필드는 금액, 날짜, 분류, 자산이며 내용은 선택 사항이다. 이체에는 분류가 없고 내용만 선택 입력한다. 이체의 `보내는 계좌`와 `받는 계좌`에는 활성 계좌 유형만 이름으로 보여주며, 음수 잔액 계좌도 같은 계좌 후보에 포함한다. 현금·카드·적금 등 다른 유형은 후보에 섞지 않는다. 계좌가 두 개 미만이면 필요한 이유를 인라인으로 알리고 저장을 막되 이미 입력한 금액·날짜·주체·내용은 보존한다. 저장 직후 목록에 낙관적 반영할 수 있지만 서버 응답이 실패하면 원래 입력을 보존해 재시도하게 한다.

원화 금액 입력은 일반 텍스트·숫자 필드와 다른 공통 `MoneyField`로 표현한다. 입력과 동시에 천 단위 콤마를 넣고, 우측 정렬한 20–24px semibold tabular 숫자와 오른쪽의 고정 `원` 단위를 56px 입력 안에 배치해 은행 앱처럼 금액을 먼저 읽게 한다. 거래 기록은 연관된 날짜 필드와 한 행에서 균형이 맞도록 금액 입력만 48px·18–20px로 compact 조합하고, 320px부터 두 필드를 같은 높이·같은 폭의 두 열로 둔다. 200% 확대처럼 실제 가용 폭이 18rem 미만이면 한 열로 돌려 가로 overflow를 막는다. 모바일의 양수 금액은 숫자 키패드를 요청하고, 음수를 허용하는 자산 최초 금액은 부호 입력을 유지한다. 붙여넣은 콤마·`₩`·`원`은 안전하게 정규화하지만 소수와 다른 문자는 값으로 바꾸지 않는다. 실제 draft와 API에는 콤마 없는 원 단위 정수만 유지하고, 오류·충돌·viewport 변경으로 사용자가 입력한 금액을 잃지 않는다.

### 자산

신규 등록은 사용자가 자산을 먼저 장부에 올리는 데 집중한다. 모든 자산은 자산 종류, 선택 입력인 자산 이름, 최초 금액과 등록일을 입력하며, 대출은 같은 금액 입력을 `대출금`으로 부른다. 종류는 `select`가 아니라 모바일에서도 한눈에 비교하고 누를 수 있는 고정 시스템 종류 버튼 그룹으로 제공하고 선택 상태를 `aria-pressed`, 글자 굵기와 색·경계 변화로 함께 표현한다. 이름을 비워 두면 종류 기반 기본명을 쓰고, 소유자 marker·메모는 신규 화면에 노출하지 않은 채 현재 사용자·없음으로 저장한다.

등록 성공 후에는 자산 목록으로 돌아간다. 사용자가 목록에서 해당 자산을 열면 이름, 소유 형태·소유자, 최초 금액·등록일, 메모를 수정할 수 있다. 같은 기본 이름의 활성 자산이 있으면 사용 가능한 가장 작은 숫자 suffix를 붙여 `계좌 2`, `계좌 3`처럼 저장한다. 상세에서 직접 입력한 이름은 종류를 바꿔도 유지하며, 이름을 지운 경우에만 현재 종류의 사용 가능한 기본 이름으로 돌아간다. `기타`는 별도의 종류 이름을 요구하지 않는 현금성 자산이고 구체적인 용도는 자산 이름으로 구분한다. `저축` 버튼은 `적금`으로 표시한다.

신용카드는 정산일, 결제 월·일, 결제 계좌를 신규 등록 흐름에 펼치고 모두 필수로 받는다. 체크카드는 `결제 계좌`를 필수로 받는다. 적금은 `자동이체 설정` switch를 기본으로 끄고 계좌·날짜 없이도 등록할 수 있게 한다. 사용자가 switch를 켠 경우에만 `자동이체 계좌`와 `자동이체일`을 함께 펼쳐 모두 필수로 받는다. 이 설정은 자동 실행 정책이 아니라 이후 상세 자동이체 설정의 출금 계좌·달력일 기반값이다. 신용카드 자동 정산은 기본으로 끈 채 저장하고 상세 수정에서 사용자가 켠다. 연결 계좌 후보가 없으면 유형별 draft를 유지하면서 `계좌 등록` 행동을 제공하고 필요한 연결 설정을 완료할 수 없는 이유를 인라인으로 알린다. 이 행동은 새 탭이 아니라 같은 화면의 dialog를 열고, 계좌 생성 성공 즉시 새 계좌를 선택한다. 입력 필드는 모바일 `320–767px`에서 한 열로 읽히게 하고, iPad·데스크톱에서만 정산일과 결제 월·일, 자동이체 계좌와 이체일처럼 짧고 연관된 필드를 병렬 배치한다.

계좌 등록 dialog는 자산 등록 폼을 중첩하지 않고 독립된 form으로 동작한다. 입력은 `계좌 이름 (선택)`, `최초 금액`, `등록일`만 제공하며 오류가 나면 그대로 유지한다. 최초 금액은 실제 `0`을 기본 입력하지 않고 빈 입력과 `0` placeholder로 시작하며, 그대로 저장하면 0원으로 처리한다. 0원이 아닌 경우에만 사용자가 값을 입력한다. 모바일·PWA를 포함한 모든 viewport에서 화면 높이를 강제로 채우지 않고 콘텐츠 높이에 맞춰 중앙에 두며, 상하 안전 여백을 남긴 최대 높이를 넘을 때만 dialog 내부를 스크롤한다. 모바일 안전 영역과 iPad·데스크톱의 제한된 읽기 폭을 유지한다. `Escape`와 브라우저 뒤로 가기는 부모 화면이 아니라 dialog를 닫고, 닫힌 뒤 trigger focus를 복원한다. modal focus 범위와 접근 가능한 이름을 제공하며 장식성 카드·중첩 표면은 추가하지 않는다.

신용카드·체크카드·적금의 연결 계좌 select 아래에는 후보 유무와 관계없이 compact한 `계좌 추가` 행동을 둔다. 후보가 없을 때만 저장할 수 없는 이유를 함께 알리고, 후보가 있으면 별도 경고 없이 추가 행동만 제공한다. 생성 성공 뒤 새 계좌가 선택된 사실을 select 값과 focus로 바로 확인할 수 있어야 한다.

신규 등록과 상세 수정 모두 입력 항목 수보다 길고 무거워 보이지 않는 compact form을 사용한다. 자산 종류는 모바일에서 3열, 큰 모바일·태블릿·데스크톱에서 5열을 기본으로 하며 긴 종류명은 버튼 안에서 줄바꿈한다. 상세 수정은 `기본 정보 · 소유 표시 · 시작 금액과 날짜` 같은 당연한 입력 묶음을 별도 단계로 나누지 않고 각 label과 간격만으로 읽는 순서를 만든다. 데스크톱의 넓은 공간도 자동 2열로 채우지 않는다. 같은 결정을 내리는 필드만 한 행에 두고, 필드 의미에 맞춘 비대칭 폭과 독립 행의 최대 너비로 시선 흐름을 만든다. 신용카드·체크카드·적금의 조건부 설정만 짧은 유형별 표지와 한 번의 구분선 아래에 펼치고, 데스크톱의 자산 빠른 이동 영역도 둥근 보조 카드가 아니라 독립된 행 목록으로 구성한다.

음수 최초 금액은 별도의 부채 토글 없이 부채로 표시한다. 최초 금액은 선택한 등록일의 자동 잔액 조정으로 처리하며 등록일 이전 거래도 막지 않는다. 소유자와 공동 소유 표시는 정보이며 모든 구성원이 수정할 수 있다는 문구를 설정 화면에서 한 번 명확히 안내한다.

활성 자산은 가계부당 50개까지 등록할 수 있다. 자산 화면에 현재 개수와 한도를 표시하고 50개에 도달하면 추가 버튼을 비활성화하면서 보관한 자산은 한도에서 제외된다는 설명을 제공한다. 동시 생성으로 서버가 한도를 거부하면 작성 중 입력을 그대로 보존한다.

새 가계부에는 생성 즉시 0원의 현금·계좌·신용카드·체크카드 행이 보인다. 사용자는 기본 자산을 즉시 열어 수정하거나 `자산 추가`로 더 만든다. 기본 신용카드는 14일 정산·25일 다음 달 결제·자동 정산 끔, 두 카드는 모두 기본 계좌 연결을 상세에서 바꿀 수 있다. `BANK` 종류는 사용자에게 `계좌`, `SAVINGS`는 `적금`으로 표시한다.

자산 첫 화면 상단은 둥근 카드 묶음이 아니라 `순자산 → 총자산·총부채 → 이번 달 카드 결제 금액·다음 달 카드 결제 예정 금액` 순서로 위계를 만든다. 순자산은 가장 큰 금액으로 한 번만 표시하고, 총자산·총부채는 계산 근거로 한 단계 작게 정렬하며 두 카드 결제 금액은 현재 자산과 섞지 않고 같은 두 열에 둔다. 이 요약은 보관 자산의 잔액과 남은 카드 결제도 포함하고, 아래 종류별 그룹과 활성 개수만 활성 자산으로 제한한다. 설명·eyebrow·상태·도구가 실제 자산을 첫 viewport 밖으로 밀지 않도록 제목·추가 행동은 한 행에 두고 활성 개수·새로고침은 낮은 위계로 압축한다.

아래 목록은 `자금 · 카드 · 투자 · 대출 · 보험`의 고정 순서로 모든 viewport에서 한 열로 이어진다. `자금`은 현금·기타·계좌·적금을 함께 읽기 위한 한 단어 화면 표지다. 마이너스 통장은 별도 종류 버튼을 두지 않고 계좌의 signed 잔액과 사용자가 정한 자산 이름으로 표현한다. 그룹명은 14px/20px semibold 본문색, 개수는 11px/16px normal muted 부가정보로 두되 16px semibold 자산 이름·그룹 합계 금액보다 낮은 시각 위계를 유지한다. 서로 다른 분류가 한 표처럼 붙지 않도록 그룹 사이 여백은 모바일 20px, iPad·태블릿 32px, 데스크톱 36px로 둔다. 각 그룹 시작에는 전체 폭의 1px 기준선과 모바일 8px·iPad 이상 12px 상단 여백을 두고, 그룹 머리 하단과 자산 행의 내부 구분선은 더 옅게 한다. 배경·아이콘·둥근 모서리·그림자는 추가하지 않는다.

`자금` 그룹은 현금·기타·계좌·적금을 함께 보여주고 그룹 `현재 합계`와 각 행 `현재 자산`을 가장 오른쪽 한 열에 정렬한다. 그룹 `현재 합계` 금액은 16px semibold를 유지하고, 개별 자금 행의 `현재 자산` 금액은 14px semibold로 한 단계 낮춰 합계와 항목을 빠르게 구분하게 한다. 값은 signed 현재 잔액 그대로여서 음수 계좌는 `-금액`, 양수는 부호 없는 금액, 0은 muted `0원`이다. 이 그룹에는 별도 `부채` 열이나 절댓값을 사용하지 않는다. 투자·대출·보험의 기존 잔액 의미는 유지한다.

자산 행의 identity는 종류·소유자 전용 고정 열을 만들지 않는다. 자산명은 16px/24px semibold로 먼저 두고 필요한 종류·소유자만 12px/16px normal muted로 뒤에 잇는다. `계좌`, `계좌 2`처럼 `종류명` 또는 `종류명 + 양의 정수`인 이름은 종류를 반복하지 않고, `월급통장`처럼 custom 이름일 때만 `· 계좌`를 붙인다. 전체 보기에서는 현재 사용자 `나`, 공동 소유 `공동`, 다른 구성원 표시명을 마지막 metadata로 붙이지만 공동·구성원 소유자별 보기에서는 선택된 소유자를 반복하지 않는다. 320~390px에서는 자산명과 metadata를 말줄임표 없이 자연스럽게 감싸 전체 텍스트를 읽게 하고, iPad 이상에서만 metadata를 남은 폭의 최대 45% 안에서 제한한다. hover로만 새 정보를 노출하지 않고 전체 종류·소유자는 링크의 접근 가능한 이름과 title, 상세 화면에 보존한다.

카드 그룹과 카드 행은 `이번 달 결제 금액 | 다음 달 결제 예정 금액` 두 열을 같은 가로줄에 두고 `부채`, `현재 부채`, `카드 부채`를 표시하지 않는다. 두 값은 항상 각각 표시하며 체크카드처럼 명세가 없으면 `0원 | 0원`으로 보여준다. 전체 카드 그룹의 두 월 합계는 16px semibold, 개별 카드 행의 두 월 금액은 14px semibold로 두어 자금 그룹과 같은 합계→항목 위계를 만든다. 320~390px에서는 자산 정보 다음 행에 두 열을 놓고 iPad·데스크톱에서는 같은 행에 정렬한다. 컬럼 label은 11px muted, 금액은 우측 정렬 `tabular-nums`와 `whitespace-nowrap`을 사용하고, DOM 순서는 자산 정보→이번 달→다음 달을 유지한다. 두 열 사이에는 카드 배경·사방 테두리·굵은 divider를 만들지 않는다.

320~390px에서 `자금`·투자·대출·보험의 단일 잔액은 이름 오른쪽 끝에 두어 목록 밀도를 유지하고, 카드만 자산 정보를 첫 행 전체에 둔 뒤 이번 달·다음 달 두 금액 열을 다음 행에 둔다. iPad·데스크톱에서는 자산 정보와 금액 rail을 같은 행에 두되 그룹 머리와 각 행의 금액 right edge를 맞춘다. 일반적인 열에 담을 수 없는 매우 긴 원화 값은 해당 행의 label과 전체 금액을 세로로 적층해 숫자 중간 줄바꿈과 페이지 overflow를 막는다. 데스크톱에서도 그룹을 두 열로 갈라 지그재그 읽기를 만들지 않으며 시계열 데이터가 생기기 전에는 현재 숫자를 반복하는 장식용 차트를 추가하지 않는다.

자산 현황 제목 옆에는 전체 활성 개수·한도만 작은 metadata로 붙이고 새로고침과 자산 추가를 같은 행동 묶음에 둔다. 활성 개수만을 위한 전체 폭 utility 행이나 구분선은 만들지 않는다. 그 아래 `소유자별 보기`는 visible 소제목이나 별도 필터 상자 없이 `전체`, `공동 소유`, 현재 사용자 이름 `(나)`, 나머지 구성원 이름이 이어지는 text subnav로 둔다. 첫 진입에는 현재 사용자 `(나)`가 선택되어 자신의 자산과 합계를 먼저 보여주며, 사용자가 전체를 선택하면 그 선택을 새로고침 뒤에도 유지한다. 각 항목은 최소 44px hit area, 투명한 배경과 하단선만 사용하며 선택 항목은 `aria-pressed`, forest 하단선, 글자색과 굵기를 함께 바꾼다. 사방 테두리·둥근 segmented control·필터별 visible 개수는 사용하지 않고 결과 개수는 보조기기에만 알린다.

소유자 subnav는 320px부터 같은 DOM의 한 줄을 유지하고 subnav 내부에서만 가로 스크롤한다. 긴 이름도 말줄임표로 숨기지 않으며 버튼 전체를 스크롤해 읽고 선택할 수 있게 한다. subnav 바로 다음에 순자산과 총부채·총자산, 이번 달·다음 달 카드 결제 rail을 두고, 정상 화면의 전체 폭 구분선은 요약 하단 한 번만 사용해 `보기 선택 → 해당 숫자 → 자산 행`이 하나의 현황으로 이어지게 한다. 결과가 없으면 큰 중앙 카드·아이콘·반복 자산 추가 행동 없이 왼쪽 정렬 문장과 전체 보기만 요약 위치에 보여준다.

### 자산 삭제와 보관

활성 자산 상세의 마지막에는 구분선 아래 낮은 위계의 `자산 정리` 행동을 둔다. 누르면 서버의 최신 삭제·보관 미리보기를 받은 뒤 하나의 확인 다이얼로그에서 결과를 설명한다. 거래 이력이 없으면 `완전 삭제`와 자산 이름을 명시하고, 거래 이력이 있으면 `보관`되어 과거 거래·통계·순자산에는 남지만 새 거래와 연결 자산 선택, 활성 자산 50개 제한에서는 빠진다고 설명한다. MVP에는 복원 기능이 없으며 최종 버튼도 결과에 맞춰 `자산 삭제` 또는 `자산 보관`으로 구분한다.

현재 잔액은 `보관 후에도 순자산에 포함됩니다`, 미결제 카드 명세가 있으면 건수와 함께 `새 카드 사용은 끝나지만 기존 결제는 계속 진행됩니다`라는 경고로 보여준다. 둘은 차단 사유가 아니므로 동의 체크나 문구 재입력을 요구하지 않는다. 최종 행동을 막는 것은 이 자산이 다른 활성 신용카드·체크카드의 결제 계좌, 자동이체를 설정한 적금의 출금 계좌이거나 미처리 카드 결제 일정의 출금 계좌인 경우뿐이다. 차단 중에는 최종 버튼을 숨기고 종류·연결 이름을 행으로 보여주며 `연결 변경` 또는 `카드 결제 설정 보기`로 바로 이동시킨다. 자동 연결 해제는 하지 않고, 사용자가 연결을 바꾼 뒤 새 미리보기를 받아야 한다. 이미 보관된 자산의 비활성 설정만 참조하면 서버는 그 참조를 유지하기 위해 완전 삭제 대신 보관 결과를 제시한다.

활성 그룹 아래에는 낮은 위계의 `보관 자산 N개 보기`를 둔다. 보관 목록은 별도 요약 카드 없이 이름·종류·소유자·부호 있는 잔액을 compact 행으로 보여주고, 미결제 카드에는 `결제 진행 중`과 다음 결제 정보를 함께 표시한다. 보관 자산을 순자산에서 빠진 것처럼 흐리게 처리하지 않고 `보관` 상태 표지를 사용하며, 활성 소유자 subnav와 활성 개수에는 섞지 않는다.

보관 자산 상세는 이름·종류·소유자·등록일·현재 잔액·보관일과 상태 설명을 읽기 전용으로 제공한다. 보관 신용카드의 명세·선결제·자동 정산 진행 정보와 과거 거래 링크는 계속 열 수 있지만 일반 수정, 새 거래와 연결 자산 선택, 복원 행동은 제공하지 않는다. 다시 사용하려면 새 자산으로 등록한다.

삭제·보관 확인은 viewport마다 다른 컴포넌트를 만들지 않고 하나의 shadcn `Dialog` DOM을 재배치한다. 모바일은 좌우 16px을 남긴 거의 전체 폭, iPad·데스크톱은 최대 36rem의 내용 높이 중앙 다이얼로그로 두고 안전 높이를 넘을 때만 본문 내부를 스크롤한다. Escape·시스템 뒤로가기는 다이얼로그만 닫고 트리거로 focus를 돌려보내며 draft와 query 상태를 유지한다.

최종 요청에는 미리보기의 `expectedVersion`과 `previewToken`을 함께 보낸다. `412`이면 최종 행동을 제거하고 `정리 결과가 달라졌어요` 경고에 focus를 옮긴 뒤 `최신 내용 다시 확인`만 제공하며, 새 미리보기를 사용자가 다시 확인하기 전에는 자동 실행하지 않는다. 새 차단 관계가 생긴 `409`, 이미 정리된 `404`, 오프라인 오류는 서로 다른 문구로 안내한다. 성공하면 활성·보관·전체 자산 목록과 상세를 함께 갱신하고 목록으로 이동한 뒤 실제 결과가 삭제인지 보관인지 알린다.

### 설치형 웹 앱

지원 브라우저에서는 홈 화면 설치 안내를 강요하지 않고 사용자가 기능을 한 번 경험한 뒤 제공한다. 설치 후에는 standalone으로 실행하되 브라우저 버전과 동일한 기능을 유지한다. 오프라인에서는 현재 입력을 보존하고 `연결되면 저장할 수 있어요` 상태를 보여주며 저장 행동을 비활성화한다. 새 버전이 있어도 작성 중 폼을 자동 reload하지 않고 저장 또는 취소 후 갱신하도록 안내한다.

### 카드 결제

카드 구매 행에는 `일시불` 또는 `할부 n/m · 결제 예정` 보조 상태를 표시하되 소비가 아직 통계에 미반영된 것처럼 보이게 하지 않는다. 선결제는 개별 구매를 고치는 행동이 아니라 여러 구매가 묶인 명세의 남은 금액을 줄이는 행동이므로 신용카드 자산 상세를 단일 진입점으로 둔다. 개별 구매 상세에는 선결제 버튼을 반복하지 않고 귀속 명세와 `카드 결제 내역 보기` 링크만 제공한다. 카드 자산 상세의 설정과 결제 내역은 같은 자산 안에 있되 `설정 변경`과 `선결제 기록`을 한 form에 섞지 않는다.

카드 자산 상세 상단은 장식성 카드 없이 가장 가까운 미결제 명세의 `남은 결제`, 결제 예정일, 결제 계좌를 먼저 보여주고 `자동 정산 사용/사용 안 함`과 `자동 정산 설정`을 한 단계 낮은 보조 행으로 둔다. `현재 부채`처럼 자산 현황과 의미가 겹치는 표현은 쓰지 않는다. 그 아래 명세는 결제 예정일 순서의 한 열 목록으로 이어지고 각 명세에 `청구 원금 · 결제 완료 · 남은 결제`를 같은 순서로 정렬한다. `선결제` 행동은 서버가 계산한 선결제 가능 금액이 0원보다 큰 명세에만 제공한다. 완료된 명세는 행동 대신 `남은 결제 0원 · 결제 완료`와 기결제 내역을 그대로 남긴다.

명세 상세의 기결제 내역은 날짜, `선결제/자동 정산`, 출금 계좌, 금액 순서로 보여주며 경제활동 주체는 표시하지 않는다. 수동 선결제의 작성자는 감사 정보가 필요한 상세에서만 낮은 위계로 보여준다. 결제와 선결제에는 `통계에 포함되지 않아요`를 한 번 명시해 일반 소비와 구분한다. 자동 정산 상태는 raw enum과 내부 오류를 노출하지 않고 `자동 정산 예정`, `처리 중`, `자동 정산 완료`, `다시 시도 예정`처럼 사용자가 다음 상태를 이해할 수 있는 문구로 변환한다. 결제 예정일이 지난 catch-up도 별도 기능명이나 실패로 부르지 않고 서버 상태가 재시도 대상일 때만 `예정일이 지났어요 · 자동 정산 다시 시도 예정`으로 안내하며, 날짜만 보고 클라이언트가 처리 실패를 추론하지 않는다.

`선결제`는 modal이나 bottom sheet가 아니라 카드·명세 맥락을 유지하는 인라인 또는 독립 화면에서 `입력 → 서버 미리보기 → 기록` 순서로 진행한다. 남은 결제액을 금액 기본값으로 제안해 전액 선결제는 한 번에 끝내되 사용자가 원 단위 일부 금액으로 바꿀 수 있고, 완료 후 같은 명세에 남아 복수 선결제를 이어갈 수 있다. 결제 계좌는 해당 카드에 설정된 계좌를 읽기 전용 자금 출처로 보여준다. 적용일은 사용자가 고르는 입력이 아니라 서버가 `Asia/Seoul`의 오늘로 확정해 미리보기에 읽기 전용으로 보여준다. 미리보기에는 현재 남은 결제, 이번 선결제, 선결제 후 남은 결제, 출금 계좌의 현재 잔액과 기록 후 잔액, 적용일을 보여주고 계좌가 음수가 되어도 오류나 경고색 대신 signed 결과와 `잔액이 부족해도 전액 기록돼요` 설명을 사용한다. 최종 행동 문구는 외부 카드사에 결제를 요청하는 것처럼 보이는 `결제하기`가 아니라 `선결제 기록`으로 한다.

입력을 바꾸면 기존 미리보기는 즉시 폐기하고 apply를 막는다. preview·apply 요청 중에는 대상 명세 version, 금액, 서버 확정 적용일, 결제 계좌를 잠가 서로 다른 계산이 섞이지 않게 한다. 두 세션 중 먼저 결제한 세션 때문에 명세 version이나 남은 금액이 달라져 `412`가 오면 내 금액 draft를 보존하고 오래된 미리보기를 폐기한다. 최신 남은 금액과 내 입력을 함께 보여준 뒤 `최신값으로 다시 계산`을 거쳐야만 기록할 수 있다. apply 중에는 최종 버튼을 비활성화하고 같은 idempotency key의 재시도는 한 결제로 취급한다. 동일 요청이 이미 처리 중이면 중복 실패를 만들지 않고 `같은 선결제를 처리 중이에요. 최신 내역을 확인해 주세요`와 재조회를 제공한다.

0원, 음수, 서버가 제시한 남은 금액 초과는 인라인 금액 오류로 미리보기를 막는다. 직접 URL로 이미 결제 완료된 명세에 들어오거나 미리보기 사이 잔액이 0원이 되면 빈 form을 보여주지 않고 `결제가 완료된 명세예요`와 기결제 내역으로 돌아가는 행동을 제공한다. 자동 정산 설정 변경은 자산 version을 쓰는 별도 저장이며 기존 결제 출처와 내역을 다시 쓰지 않는다.

카드 명세 목록은 같은 DOM을 container query로 재배치한다. 320~390px에서는 `예정일·상태` 다음 줄에 세 금액을 동일한 3열로 놓고, `선결제`는 다음 줄의 명확한 44px 행동으로 둔다. iPad 세로에서는 명세 정보와 세 금액을 두 줄 grid로, iPad 가로·데스크톱에서는 `예정일·상태 | 청구 원금 | 결제 완료 | 남은 결제 | 행동`의 한 행 grid로 맞춘다. 기결제 내역도 모바일에서는 날짜·종류와 계좌·금액의 두 줄, 넓은 화면에서는 한 행으로 바꾸며 가로 스크롤과 사방 테두리 표를 만들지 않는다. 금액은 `tabular-nums`, 우측 정렬, 중간 줄바꿈 금지를 유지한다.

각 명세 영역은 결제 예정일과 상태를 포함한 접근 가능한 이름을 가지며 `선결제` 버튼의 접근 가능한 이름에는 대상 결제 예정일을 포함한다. 미리보기 완료 시 제목으로 focus를 옮기고, 오류·`412` 요약은 focus 가능한 `role="alert"`, 처리 상태 변화는 `aria-live="polite"`로 알린다. 상태는 색만으로 구분하지 않고 문구를 함께 제공한다. 200% 확대와 320px에서 가로 overflow가 없어야 하고, viewport 회전·breakpoint 변경 뒤에도 입력, 미리보기 폐기 여부, focus가 유지되어야 한다.

카드 결제 흐름은 다음을 자동 검수한다.

- 카드 구매 상세에는 명세 링크만 있고 카드 자산 상세의 해당 명세에서만 선결제를 시작할 수 있다.
- 같은 명세에 부분 선결제를 두 번 기록하면 각 결제 내역과 감소한 남은 결제가 보이며, 마지막 전액 기록 뒤 선결제 행동이 `결제 완료`로 바뀐다.
- 출금 계좌 잔액보다 큰 금액도 preview와 apply가 성공하고 기록 후 signed 음수 잔액이 정확히 보인다.
- 자동 정산 사용 여부, 출금 계좌, 예정일, 완료·재시도 상태가 명세 금액과 섞이지 않고 동일한 서버 상태를 나타낸다.
- 두 세션이 같은 version으로 preview한 뒤 한쪽이 먼저 기록하면 다른 쪽 apply는 `412`로 전체 거부되고 draft를 보존한 재계산 없이는 재적용할 수 없다.
- apply 버튼 연타와 네트워크 재시도가 결제 한 건만 만들고 처리 중·성공 뒤 명세와 출금 계좌 query를 최신화한다.
- `390×844`, `768×1024`, `1180×820`, 200% 확대에서 같은 정보와 행동을 유지하고 페이지 가로 overflow, focus 유실, 44px 미만 행동이 없다.
- 키보드와 화면 읽기 도구만으로 명세 선택, 금액 입력, 미리보기, `412` 복구, 최종 기록과 결과 확인을 끝낼 수 있다.

카드 결제에는 사람을 거래 주체로 표시하지 않고 `어느 계좌에서 빠졌는지`를 우선한다. 결제 계좌 잔액이 음수가 되어도 정산은 전액 기록되며, 음수 잔액을 오류 상태로 보이지 않는다. 결제 예정일은 비영업일이면 다음 한국 영업일로 순연된다고 안내한다.

카드 구매 상세에는 `기록 정정`과 `환불 처리`를 서로 다른 행동으로 보여준다. 기록 정정은 원 결제일의 기록을 고친다는 점과 소급 영향을 확인시키고, 환불 처리는 실제 환불일과 원 결제 계좌로 돌아갈 금액을 저장 전에 보여준다. 저장 후에는 사용자가 별도 보정 거래를 만들지 않아도 카드·결제 계좌 원장이 자동으로 일치해야 한다.

일별 원장의 카드 구매와 `환불 +금액` 행은 모두 같은 원 구매 상세로 연결한다. 정정·환불 폼은 바로 저장하지 않고 `변경 내용 확인`·`환불 내용 확인`으로 서버가 계산한 미결제 감소와 계좌별 장부 반환을 먼저 보여준다. preview·apply 요청 중에는 확인 대상 draft를 잠시 잠그고 응답과 다른 입력이 혼합되지 않게 한다. `412`에서는 draft를 보존하고 기존 preview를 폐기한 뒤 서버 최신값과 내 입력을 비교해 `최신값으로 영향 다시 계산`을 거쳐야만 apply할 수 있다. 환불일에 다른 지출이 없어 일별 지출 합계가 음수가 되더라도 달력에 `환불 +금액`을 생략하지 않는다. 환불은 수입이 아니므로 수입 색을 쓰지 않고 문구와 금액 부호로 의미를 함께 전달한다.

### 분류와 삭제

공동 분류 관리는 설정의 독립 `분류 설정` 화면에서 수입·지출을 버튼으로 전환하고 현재 방향의 분류를 compact 버튼 모음으로 제공한다. 모바일 320px부터 가용 폭에 맞춰 최소 112px·44px 높이의 열을 자동 배치하고, iPad·데스크톱에서도 같은 DOM을 재배치한다. 각 버튼은 이름만 우선해 보여주며 긴 이름은 최대 두 줄로 제한하고 전체 이름은 접근 가능한 이름·`title`·선택 관리영역에서 제공한다. 선택 상태는 `aria-pressed`와 색 이외의 테두리·굵기를 함께 사용한다.

분류 버튼을 선택하면 그 분류 하나의 전체 이름, 연결 거래 수, 이름 수정과 삭제 행동을 버튼 모음 아래에 보여주고, 넓은 화면에서는 얇은 세로 구분선 오른쪽에 둔다. 선택하지 않은 분류의 수정·삭제 아이콘과 거래 수를 반복 노출하지 않는다. 기본 `기타`는 선택과 이름 변경이 가능하지만 삭제 행동은 노출하지 않고 fallback 용도를 안내한다. 분류 삭제 확인에는 실제 연결 건수와 같은 방향의 `기타`로 이동함을 명시하고 완료 후 이동 건수·기간을 알린다.

거래 기록에서 분류 trigger를 누르면 모바일은 safe area 위의 하단 drawer, iPad·데스크톱은 compact dialog로 같은 picker를 연다. 분류는 최소 44px의 compact 버튼 grid로 표시하며 현재 선택은 `aria-pressed`, check, 경계와 굵기로 함께 나타낸다. 목록의 마지막은 `항목 추가` 버튼이고, 누르면 같은 overlay 안에서 공동 분류 이름 입력과 `목록으로 · 추가` 행동을 보여준다. 성공하면 새 항목을 선택하고 overlay를 닫으며 금액·날짜·자산·사람·내용 draft는 그대로 둔다. 중복·서버 오류·오프라인에서는 이름 입력과 overlay를 유지하고, 취소·`Escape`·바깥 영역 선택 뒤에는 분류 trigger로 focus를 복구한다.

거래 주체는 native select나 사람 목록 overlay 대신 현재 구성원이 기본 선택된 compact person radio group으로 고른다. 각 option은 한 글자 식별자, 전체 표시명, 현재 사용자의 `나` 표식과 명시적인 radio 상태를 한 줄에 두고 전체 영역을 눌러 선택할 수 있게 한다. 후보는 모바일부터 최소 44px 조작 영역을 유지하며 가용 폭에 따라 자동 줄바꿈하고, 선택은 색뿐 아니라 radio·경계·배경·굵기로 함께 구분한다. 거래 종류가 바뀌면 질문만 `누가 받았나요? · 누가 썼나요? · 누가 옮겼나요?`로 바꾸고 같은 선택과 다른 draft를 보존한다.

자산 소유자 선택도 같은 compact person radio group을 사용한다. 자산 소유자 subnav·자산 행, 일별 거래 행·거래 상세·입력 요약, 통계의 구성원·소유자 필터에는 동일한 구성원 avatar를 이름 옆에 둔다. 같은 구성원은 화면마다 같은 색과 첫 글자를 사용하고 현재 사용자는 `나`, 공동 소유는 공동 icon과 문구를 함께 표시한다. 작은 avatar는 부가 식별 수단이므로 자산명·내용·금액보다 시각적으로 크거나 단독 label이 되지 않는다.

가계부 전체 삭제는 설정 맨 아래의 구분선 뒤 `파괴적 작업`에만 둔다. 첫 행동은 바로 삭제하지 않고 하나의 modal dialog를 열며, 가계부의 모든 구성원·자산·기록·초대가 함께 영구 삭제되고 구성원 계정과 로그인은 유지된다는 영향을 먼저 설명한다. 사용자가 `가계부 삭제`를 정확히 직접 입력해야 최종 파괴 버튼이 활성화된다. `412`이면 입력을 보존하고 dialog 제목으로 focus를 옮겨 다른 변경이 있었음을 알린 뒤 최신 가계부 정보를 다시 불러와야 하며 자동 재시도하지 않는다. 성공하면 dialog를 닫고 가계부 시작·초대 코드 화면으로 이동한다.

일반 거래 행은 상세·수정 화면으로 이어진다. 유형은 읽기 전용이고 금액·날짜·분류·자산·거래 주체·내용만 고친다. 삭제 전에는 잔액과 달력 합계가 함께 바뀐다는 짧은 확인을 보여준다. 신용카드 구매에는 일반 수정·삭제 대신 `기록 정정`·`환불 처리` 진입점만 제공하며, 시스템 거래는 읽기 전용으로 표시한다.

## 공동 편집과 최신값 확인

- 저장 성공 응답으로 현재 작성 세션의 관련 데이터만 갱신한다.
- 다른 멤버의 변경은 화면 진입, 브라우저 탭 재집중, 사용자의 새로고침에서 확인한다.
- 편집 시작 때 읽은 version과 저장 시점 version이 다르면 `412` 충돌로 저장을 막고 어떤 필드도 자동 병합하지 않는다.
- 충돌 화면은 서버 최신값과 보존한 내 입력을 비교해 `최신값에 내 입력 다시 적용` 또는 `취소`를 선택하게 한다.
- 연결 중단 시 읽기는 유지하고 쓰기 전에 오프라인 상태를 명확히 알린다.
- 다른 사용자가 조회 중인 거래나 자산을 삭제한 사실을 재조회 또는 저장 응답에서 확인하면 상세 화면을 닫고 목록 복귀를 한 번만 알린다. 편집 중이라면 draft를 지우지 않고 입력 복사, 새 항목으로 저장, 저장 없이 목록 복귀를 선택하게 한다.

비동기 상태는 `첫 로딩`, `백그라운드 갱신`, `mutation 저장 중`, `오프라인 stale`, `재연결`, `403`, `409/412 충돌`, `원격 삭제`, `복구 불가능 오류`로 구분한다. 전체 화면 skeleton은 첫 로딩에만 사용하고 백그라운드 갱신으로 기존 데이터를 가리지 않는다.

## 테마와 지원 브라우저

테마 선택은 `시스템 설정 · 라이트 · 다크` 세 가지다. 첫 방문은 `prefers-color-scheme`을 따르고 사용자가 바꾸면 해당 기기의 local storage에만 기억한다. 앱이 그려지기 전에 저장된 선택을 적용해 밝은 화면이 잠깐 번쩍이지 않게 하며, 서버 계정 설정으로 동기화하지 않는다.

Chromium 모바일·데스크톱, Edge, macOS/iOS/iPad Safari를 공식 지원하고 Firefox는 핵심 smoke 범위로 둔다. 테마별 로고·명암·focus ring과 200% 확대를 공식 브라우저에서 검수한다.

모바일 push형 상세·입력 화면은 전체 폭 `돌아가기` 행을 본문에 반복하지 않고, safe area를 반영한 sticky 상단 바에 icon 뒤로가기·현재 화면 `h1`을 한 줄로 둔다. 하단 dock은 왼·오른쪽·하단 모서리에서 12px 이상과 safe area를 띄우고 20~24px radius의 단일 불투명 표면과 최소한의 그림자만 사용한다. glassmorphism과 tab별 장식 카드는 사용하지 않는다.

모바일 달력은 320px에서도 7개의 날짜 hit area를 확보하도록 화면 좌우 여백보다 넓은 full-bleed 영역을 허용하지만 페이지 전체 가로 스크롤은 만들지 않는다. 좁은 화면에서 표의 열을 단순히 숨겨 의미를 잃게 하지 않고 의미를 보존한 compact row로 재구성한다. 축약한 금액과 잘린 이름의 전체 값은 상세와 접근 가능한 이름에서 제공한다. 파괴적 행동은 swipe·hover에만 숨기지 않는다.

모바일 Sheet와 고정 행동은 `safe-area-inset-*` 네 방향과 동적 viewport 높이를 반영한다. iPad의 touch·keyboard·trackpad를 모두 고려하고 hover 없이 모든 기능을 사용할 수 있어야 한다. resize와 회전은 route, 가계부, 월·날짜, 필터, 선택 상세, scroll, focus, 작성 중 draft를 보존하며 UI 형태가 Sheet에서 panel로 바뀌어도 폼과 TanStack Query 상태를 재마운트하거나 초기화하지 않는다.

## shadcn 구현 기준

| UX 요소 | 기반 컴포넌트/variant |
|---|---|
| 주요·보조·파괴 행동 | Base UI 기반 Button `default / secondary / destructive`; 링크는 `render` 합성 |
| 거래·자산 입력 | Form, Input, Textarea, Calendar, Checkbox, Switch, RadioGroup |
| 원화 금액 입력 | Input 기반 MoneyField; 실시간 천 단위 구분·우측 정렬·고정 `원` 단위 |
| 짧은 단일 선택 | NativeSelect; 모바일 OS picker와 키보드·자동완성을 우선 |
| 긴 검색형 선택 | Combobox; 실제 검색 필요성과 후보 규모가 생길 때 적용 |
| 자산 종류 선택 | 실제 Button 기반 단일 선택 그룹, `aria-pressed`와 반응형 배치 |
| 거래 주체 선택 | RadioGroup 기반 compact person option; 식별자·이름·`나`·명시적 radio 상태 |
| 모바일 상세·기록 | 하나의 Dialog를 모바일 Sheet·데스크톱 panel로 CSS 재배치 |
| 분류 선택·즉시 추가 | Dialog 기반 버튼 picker; 동일 overlay 안에서 추가 후 즉시 선택 |
| 피드백 | inline Alert 우선, 완료만 짧은 Toast |
| 충돌·원격 삭제 | AlertDialog가 아닌 보존 가능한 conflict panel |

공통 primitive는 `components/ui`에서만 HTML control을 소유하고 기능 화면은 이를 조합한다. shadcn 최신이라는 이유만으로 custom Select나 Combobox를 일괄 적용하지 않고 후보 수, 검색 필요성, 모바일 입력 비용을 기준으로 고른다. Overlay는 Base UI의 focus 관리와 접근 가능한 Title·Description을 사용하고, 돈독의 44px touch target·4~6px control radius·최대 8px overlay radius를 토큰으로 덧입힌다.

모든 기능 handoff는 API 상태에서 TanStack Query의 `initial/pending/success/error/stale/fetching`과 화면 상태로 이어지는 전이표를 포함한다. optimistic update를 사용하는 mutation은 rollback 데이터와 사용자 입력 보존 위치를 명시한다.

## 문장과 피드백

짧고 구체적인 존댓말을 쓴다. `실패했습니다` 대신 `거래를 저장하지 못했어요. 입력은 그대로 두었습니다.`처럼 결과와 다음 행동을 알려준다. 장난스러운 축하 문구, 부부 관계를 가정하는 호칭, 소비를 평가하는 표현을 쓰지 않는다.

## UX/UI ↔ Frontend 협업 규칙

각 기능은 다음 순서로 넘긴다.

1. UX/UI가 목적, 사용자 흐름, 정보 우선순위, 모든 상태와 모바일·iPad 세로/가로·데스크톱 동작을 문서화한다.
2. Frontend가 shadcn 재사용 가능성, 토큰, 접근성, 서버 계약과 TanStack Query 상태 모델을 검토한다.
3. 차이는 코딩 전에 문서에서 합의하고 공통 컴포넌트와 기능 전용 컴포넌트 경계를 기록한다.
4. Frontend 구현 후 UX/UI가 대표 viewport와 breakpoint 양쪽 경계에서 실제 브라우저를 검수한다.
5. QC가 합의된 접근 가능한 이름, 사용자 결과, 회전·resize 상태 보존을 Playwright 인수 조건으로 고정한다.

기능별 인수 항목에는 최소한 다음이 포함된다.

- 정상, 로딩, 빈 상태, 오류, 권한과 무관한 비활성, 오프라인, 재연결, 동시 수정 충돌
- 키보드 순서, 접근 가능한 이름, 오류 연결, 포커스 복구
- 실제 긴 이름·큰 금액·N명 멤버·한글 줄바꿈
- 터치 목표, safe area, 대표 viewport와 breakpoint 경계의 가로 overflow 여부
- 회전·resize 전후 draft·필터·focus·scroll·서버 상태 보존
- 서버 성공·실패 시 TanStack Query 캐시와 사용자 입력 보존 방식

회원가입·이메일 인증·로그인 첫 화면이 구현되었으며 이 문서는 이후 화면에도 적용하는 구현 계약이다. 각 화면은 UX/UI 검수와 Frontend 수정, 대표 viewport 브라우저 검증이 끝나야 완료로 처리한다.
