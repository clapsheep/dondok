# 돈독 UX 가이드

> **2026-10-09 D-086 적용:** 아래 이전 시각 규칙 중 카드형 표면 금지, 반복 구분선, 4–8px radius 제한, 중립 회색 선택 및 수입 우선 요약은 승인된 기록·자산·통계 시안으로 대체한다. 금융 의미와 접근성·상태 보존 계약은 유지한다. 실행 토큰은 `frontend/src/index.css`, 공통 레이아웃은 `components/ui/data-layout.css`가 원본이다. 선택 컨트롤은 8–12px, 요약 표면은 18–20px, overlay는 16px radius를 사용하며 일반 행은 여백으로 구분한다. 라이트는 흰 배경·옅은 녹색 회색 표면·초록 선택, 다크는 `#171A19` 배경·`#222725` 표면·`#DBEE8B` 선택을 사용한다. 주요 행동은 별도 초록 `--action` 토큰을 사용한다. 과거 팔레트의 대비 수치는 새 토큰의 검증 근거로 사용하지 않는다.

## 제품 경험

돈독은 회계 지식 없이도 둘 이상의 구성원이 같은 장부를 안심하고 기록하는 서비스다. 기본값은 가장 흔한 행동을 빠르게 만들고, 카드 정산처럼 복잡한 규칙은 필요할 때만 단계적으로 보여준다.

## 모바일 우선 정보 구조

모바일 하단 내비게이션은 `홈 · 기록 · 자산 · 통계 · 설정` 다섯 항목을 기본으로 한다. 기록은 독립된 탭이지만 크기나 애니메이션으로 과장하지 않는다. 홈 자체가 공동 가계부이며 월간 달력과 일별 원장을 보기 전환으로 제공한다. 홈과 통계의 구성원별 보기는 모두 현재 사용자를 기본으로 하고 `나 · 각 구성원 · 모두` compact 선택을 사용한다. 통계의 자산 소유자·분류 조건만 별도의 세부 필터로 둔다. 설정은 하단 내비게이션에서 바로 열고 로그아웃은 설정 안에서만 제공해 일반 화면 상단의 공간을 사용하지 않는다. 다섯 탭의 dock은 각 페이지가 소유하지 않고 앱 route 바깥의 지속되는 chrome으로 유지해 탭 이동과 긴 목록 렌더링 중 DOM·safe-area 좌표·크기가 교체되거나 흔들리지 않게 한다.

데스크톱(1280px 이상)은 높이 64px의 고정 상단 내비게이션을 사용한다. 왼쪽의 28px 높이 워드마크 다음에 `홈 · 기록 · 자산 · 통계` 텍스트 메뉴를 한 줄로 두고 설정은 오른쪽 끝에 아이콘·글자로 분리한다. 기본 메뉴는 medium 보조색, hover는 옅은 중립 배경, active는 semibold 초록색 글자와 2px 밑줄로 구분한다. 본문과 메뉴의 콘텐츠 최대 폭은 82rem이며 좌우 32px 여백을 맞춘다. 데스크톱 왼쪽 여백은 제거하고 본문 시작과 sticky 날짜·요약 위치에는 상단 높이를 반영한다. 정보 구조와 명칭은 화면 크기에 따라 바꾸지 않는다.

기능을 단계적으로 공개하는 개발 단계에서는 아직 동작하지 않는 메뉴를 비활성 자리로 노출하지 않는다. 최종 모바일 dock은 `홈 · 기록 · 자산 · 통계 · 설정`을 같은 순서로 제공하고 iPad에서는 네 데이터 메뉴와 하단 설정, 데스크톱에서는 네 상단 메뉴와 오른쪽 설정으로 시각적 위계만 나눈다. 모바일 일반 홈·기록·자산·통계·설정 화면은 브랜드·설정·로그아웃·뒤로가기를 위한 상단 바 없이 safe area 다음에서 콘텐츠가 바로 시작한다. push형 상세·수정 화면에만 뒤로가기와 현재 제목을 담은 한 줄 상단 바를 둔다. 설정 첫 화면은 dock·rail·상단 메뉴로 이동할 수 있으므로 별도 `가계부로 돌아가기` 행을 만들지 않는다.

## 카드 없는 페이지 구성

제품 페이지는 반복되는 카드 컨테이너로 정보를 나누지 않는다. 한 화면 안의 섹션은 같은 배경 위에서 이어지고, 의미 있는 제목·일관된 간격·열 정렬·필요한 최소 구분선으로 관계를 표현한다. 폼은 하나의 연속된 `form` 안에서 `fieldset`과 `legend`를 사용하며, 조건부 필드도 기존 흐름 아래에 인라인으로 펼친다. 거래 폼은 금액부터 내용까지 하나의 일정한 세로 흐름으로 두고 `금액+날짜`, `분류+자산`, `사람+내용`처럼 관련 없는 두 필드씩 묶거나 묶음별 가로선을 넣지 않는다. 섹션마다 배경·네 방향 테두리·radius·그림자를 함께 주거나 표면을 중첩하지 않는다.

입력과 버튼의 테두리, 선택 상태와 focus ring은 조작 가능성을 알리는 컨트롤 표현이므로 이 원칙의 예외가 아니다. 별도 표면과 그림자는 dialog, sheet, popover, toast, PWA 갱신 prompt처럼 현재 페이지 위에 실제로 떠야 하는 요소에만 허용한다. 빈 상태·오류·한도 도달 안내는 해당 목록이나 폼 영역 안에 문구와 행동을 바로 배치한다.

## 홈 가계부

D-092 승인 시안에 따라 모든 화면 크기에서 `가계부` 제목과 기록 행동을 표시한다. 월 지출을 중심으로 수입·차액을 중립색으로 표시하는 하나의 요약 표면을 둔다. 구성원 소개·초대 행동은 설정에서 제공한다.

- `나 · 각 구성원 · 모두`는 공통 avatar와 이름, 부드러운 선택면으로 표현한다. N명·긴 이름은 구성원 영역 안에서 가로 스크롤한다. 구성원 변경은 월 합계·달력·선택 날짜·일별 목록에 함께 적용하고 URL로 유지한다.
- 월별 보기는 7열의 얇은 날짜 격자다. 날짜·금액·건수는 위쪽 왼편에 정렬하고 인접 월 날짜는 흐리게 표시한다. 수입은 빨간색 `+금액`, 지출은 파란색 `-금액`, 순환불은 파란색 `+금액`과 환불 설명을 유지한다(D-072). 일반 이체·집계 제외·삭제·기준일 잔액은 집계 건수에서 제외하고 카드결제는 별도로 표시한다.
- 오늘과 선택일, 토요일·일요일을 구분하며 날짜 전체를 선택할 수 있다. 금액은 셀 안에 말줄임 없이 축약하고 접근 가능한 이름에 정확한 원 금액과 건수를 제공한다.
- 선택일 내역은 넓은 화면에서 달력 오른쪽, 좁은 태블릿에서는 아래에 배치한다. 모바일(767px 이하)은 날짜를 누르면 약 72dvh 하단 시트로 열고 핸들 클릭·위로 드래그로 확장한다. 날짜 이동·합계·기록 행동은 고정하고 거래 목록만 스크롤한다. 닫기·Escape·아래로 드래그·뒤로 가기는 달력 위치와 선택일을 유지한다. 동일 DOM을 유지하고 회전으로 날짜·필터·query 상태를 초기화하지 않는다. safe area와 reduced-motion을 따른다.
- 날짜 내역에는 이전/다음 날, 정확한 금액, 거래 목록과 선택일을 전달하는 기록 링크가 있다. 이동은 월·연도 경계를 지원한다. 날짜와 모바일 시트 열림(`detail=day`)은 URL에 저장하며 새로고침·브라우저 뒤로 가기로 복구한다. 모바일에서는 동일 패널을 native modal dialog로 열어 포커스를 가두고 배경 스크롤을 잠근다.
- 일별 보기는 전체 폭의 기존 거래 목록을 사용한다. 검색·종류·기간 필터와 cursor pagination, 날짜별 sticky 제목, 거래 상세 이동을 유지한다.
- 각 query의 로딩·빈 상태·오류와 오프라인 안내를 해당 영역에 표시한다. 새로고침과 모바일 pull-to-refresh는 활성 query를 재조회하며 API 데이터의 service worker cache를 사용하지 않는다.

## 공동 월간 통계

통계 첫 진입은 `Asia/Seoul`의 이번 달과 필터 없는 `공동 전체`다. 헤더는 `통계`, 이전 달, `YYYY년 M월`, 다음 달, `공동 전체 · 필터`, `최신값 확인` 순서로 두고, 별도 `이번 달` 복귀 버튼은 제공하지 않는다. 월과 적용된 필터, 분류 비중 방향은 `/statistics` search parameter를 source of truth로 삼아 새로고침·뒤로 가기·PWA 재실행·viewport 변경에도 유지한다.

월 요약은 구조적 카드 세 개가 아니라 전체 폭의 얇은 위·아래 구분선 사이에 `수입 · 지출 · 총계` 순서의 하나의 `dl`로 둔다. 지출은 생활 지출 순금액과 적금·투자 납입 합계이며, 총계는 수입에서 이 총 사용액을 뺀 값이다. 수입 금액은 기존 `--income` 초록, 지출 금액은 `--expense` 붉은색, 총계는 기본 검정(다크 모드 기본 밝은색)으로 표시한다. 수입은 양수, 지출은 자금 감소 부호이며 순환불은 양수가 된다. 원 단위 전체값과 `tabular-nums`를 사용하고 색에만 의미를 의존하지 않는다.

필터 trigger는 아무 조건이 없으면 `공동 전체`, 적용 후에는 선택한 값을 짧게 나열하고 `필터 2개`처럼 개수를 함께 알린다. 하나의 responsive filter panel/dialog 안에 `거래 주체`, `자산 소유자`, `분류` 세 `fieldset`을 두고 각 그룹은 `전체`를 포함한 단일 선택 radio로 구현한다. 거래 주체는 작성자가 아니라 실제 경제활동 주체, 자산 소유자는 거래의 주 자산에 붙은 현재 소유 marker임을 label로 구분하고 분류 선택지는 `식비 · 지출`처럼 방향을 함께 표시한다. 그룹 안에서는 한 값만 선택하고 선택된 서로 다른 그룹은 AND로 적용한다. panel draft는 `적용` 전까지 결과를 바꾸지 않으며 `초기화`는 세 그룹을 모두 `전체`로 되돌린다.

filter panel/dialog는 viewport별 별도 컴포넌트나 중복 DOM을 만들지 않는다. 동일한 form·focus 범위·draft를 모바일에서는 하단 안전 영역을 반영한 sheet 형태, iPad·데스크톱에서는 폭이 제한된 panel/dialog 형태로 CSS 재배치한다. 열고 닫기, 회전과 breakpoint 통과에서 선택 draft를 유지하고 닫으면 trigger focus를 복원한다. `Escape`와 브라우저 뒤로 가기는 먼저 panel만 닫는다. trigger는 `aria-expanded`와 연결된 panel 이름을 제공하고, 적용 뒤 결과 범위 변경을 `aria-live="polite"`로 한 번 알린다.

통계는 수입·지출·총계 요약 → 통합 사용처 순위 → 연간 흐름 → 접힌 납입·회수 상세 순서로 제공한다(D-070). 사용처 순위에는 식비·주거비 등 각 지출 분류와 적금·투자 납입을 동일한 수준으로 배치하고 금액순으로 정렬한다. 소비 합계 한 행과 세부 분류를 중복 배치하지 않는다. 순위 숫자·항목 이름·정확한 금액·총 사용액 대비 비율을 가로 막대 바로 위에 표시한다. 사용액은 양수, 순환불은 음수다. 막대는 최댓값 기준 길이를 유지하고 코랄·청록·블루·퍼플·앰버·로즈·스카이 악센트로 항목을 구분한다. 분류 이름 기준의 일관된 색을 사용해 순위·월 변경만으로 색이 바뀌지 않게 하며, 적금은 퍼플·투자는 블루로 연간 범례와 연결한다. 밝고 어두운 화면에 각각 막대 팔레트를 두되 금액·순위 글자는 기본 중립색을 유지한다. 순위 배지의 색 배경은 사용하지 않고 track도 중립색으로 두어 색 강조를 막대와 범례 표지에 한정한다. 금액·이름·비율은 항상 문자로 제공하며 색은 수입·지출의 부호를 대신하지 않는다.

기본 `사용처`와 보조 `수입` 전환을 유지한다. 상위 6개를 먼저 보여주고 `전체 N개 보기`로 원래 이름을 유지한 채 펼친다. 지출/수입 분류 행은 기존 거래 내역을 열고 적금·투자 납입 행은 납입 표기를 붙인 정적 요약이다. 납입 0원은 순위에 추가하지 않고 회수는 하단 `적금·투자 납입과 회수 자세히 보기`에서 확인한다.

환불 때문에 선택 방향 전체 순금액이 0 이하라면 해당 방향의 모든 비율·막대를 숨기고 signed 금액 행만 유지한다. 전체 합계는 양수여도 하나 이상의 분류 순금액이 0 이하이면 양수 항목만의 비율이 전체를 왜곡하므로 방향 전체의 비율·막대를 함께 숨긴다. 이 상태에는 `환불을 반영해 비율 대신 분류별 순금액을 보여드려요`를 한 번 안내하며 음수 분류를 오류색이나 실패 상태로 표현하지 않는다.

연간 흐름은 1~12월의 수입·소비·적금 납입·투자 납입을 공통 최댓값으로 비교하는 묶음 막대다. 색과 문구 범례를 함께 표시하며 12개 월 label을 같은 폭 안에 유지한다. 정확한 수입·소비·납입·회수 금액은 펼칠 수 있는 `월별 금액 목록`에서 확인한다. 순환불이 있는 연도에는 소비 막대가 크기 기준임을 안내하고 목록에 signed 값을 표시한다. 별도 chart dependency나 애니메이션은 추가하지 않는다.

320~767px에서는 월 선택과 필터 행동을 자연스럽게 두 줄로 감싸고 요약을 `수입·지출` 두 열과 전체 폭 `총계`의 다음 행으로 둔다. 태블릿·데스크톱은 요약 세 값을 한 행에 두며 모든 크기에서 통합 순위와 연간 흐름을 한 열로 이어간다. 긴 항목명과 금액은 행 내부에서 줄을 나누고 viewport 변경으로 순위 펼치기·필터·focus 상태를 초기화하지 않는다.

처음 조회와 새 월·필터 적용은 결과 영역 높이를 크게 바꾸지 않는 금액·행 skeleton을 사용하고, 같은 query의 background refetch는 기존 값을 가리지 않은 채 `최신값 확인 중`만 알린다. 이전 조건의 값을 새 조건 label 아래에 그대로 보여주지 않는다. 기록이 전혀 없는 월은 0원 요약과 `이번 달 수입·소비·적금·투자 기록이 없습니다`·`기록하기`를, 적용 필터 결과가 없으면 `선택한 조건에 맞는 기록이 없습니다`·`필터 초기화`를 보여준다. 선택 월이 비어도 같은 연도의 다른 달 기록이 있으면 연간 막대는 유지하고, 연도 전체가 비면 `YYYY년에는 수입·소비·적금·투자 기록이 없습니다`를 표시한다. 한 방향만 비면 해당 분류 영역에만 `이번 달 지출이 없습니다` 또는 `이번 달 수입이 없습니다`를 표시하고 다른 방향과 연간 막대는 유지한다. 첫 조회 실패는 같은 영역의 재시도, background refetch 실패는 기존 결과와 인라인 최신값 재시도를 제공한다. 오프라인에서는 마지막으로 앱 메모리에 남은 결과가 있으면 조회 시점과 갱신 불가를 알리고 금융 데이터를 service worker에 저장하지 않는다.

통계 요약은 `dl`, 분류 행은 실제 text와 signed 원화값, 연간 대체 목록은 월별 `time`과 `dl`을 사용한다. 가로 막대 목록과 연간 막대그래프에는 방향·연도를 포함한 접근 가능한 이름을 제공하고 세부 수치 탐색은 바로 이어지는 실제 행이 담당한다. 월 이동, filter trigger·radio·적용·초기화, 분류 방향, 목록 펼치기의 hit area는 44px 이상이다. 긴 구성원·분류명은 시각적으로 말줄임해도 접근 가능한 이름과 filter panel에 전체를 남긴다. `320×568`, `390×844`, `768×1024`, `1180×820`, 200% 확대에서 원 단위 금액 중간 줄바꿈, 전체 페이지 가로 overflow, chart label 겹침, filter·focus 유실이 없어야 한다.

## 핵심 흐름

경제활동일·잔액 기준일처럼 `DATE`를 입력하는 모든 필드는 브라우저의 네이티브 `date` 컨트롤을 사용한다. 사용자가 입력 영역 어디를 클릭해도 기기와 브라우저에 맞는 달력 선택 UI를 열고, 키보드와 직접 입력도 그대로 지원한다. 달력 UI 지원 여부와 관계없이 서버에 전달하는 값은 기존 `YYYY-MM-DD` 계약을 유지한다.

### 가입과 연결

가입 후 아직 참여한 가계부가 없다면 `초대 코드를 받으셨나요?`를 먼저 묻고 다음 두 행동만 보여준다.

- 받지 않은 사용자는 `바로 시작하기`로 이름 입력 없이 새 가계부를 생성
- 받은 사용자는 `초대 코드 입력하기`로 이동해 숫자 6자리 입력

첫 화면에 코드 입력란을 함께 펼치지 않는다. 링크로 들어온 사용자는 별도 입력 없이 초대 미리보기를 보고, 직접 참여 화면에서는 모바일 숫자 키패드·6자리 길이 제한·가운데 정렬된 tabular 숫자로 짧은 코드를 입력한다. 참여 완료 후 홈으로 진입한다.

가입은 로그인 아이디, 이름, 이메일, 비밀번호를 받는다. 로그인 아이디는 상대 검색에 사용하지 않으며 공개 핸들·사용자 검색도 제공하지 않는다. 숫자 6자리 직접 입력 코드와 별도 초대 URL은 인증 식별자와 분리되어 있음을 문구로 설명한다.

로그인 성공 후에는 브라우저·설치형 PWA를 닫아도 같은 기기에서 자동 로그인한다. 별도 자동 로그인 선택이나 비밀번호 저장 UI를 추가하지 않고, 서버의 30일 미사용·90일 절대 만료와 명시적 로그아웃을 따른다. 공용 기기 사용자는 로그아웃으로 현재 기기 세션을 즉시 종료할 수 있어야 하며 클라이언트 저장소에는 비밀번호나 세션 ID를 저장하지 않는다.

한 사용자는 하나의 가계부에만 참여한다. 초대 수락 성공 즉시 홈으로 이동하고 초대 화면은 종료한다. 이미 참여한 사용자가 초대 URL을 다시 열면 확인 화면을 보여주지 않고 홈으로 이동한다. 가계부 설정에서 새 멤버 초대와 여러 발신 초대의 `사용 가능 · 만료 · 사용 완료` 상태를 관리하며, 초대 대기 상태가 홈 진입을 막거나 N명 가계부 전체를 2인 연결 대기 화면으로 되돌리지 않는다. 개인 나가기 UI는 제공하지 않는다.

가계부 생성은 이름 입력 없이 `바로 시작하기` 한 번으로 완료한다. 참여 후 공동 공간은 고정 화면 제목으로 안내하고, 이름 변경이나 가계부 전환 UI를 만들지 않는다. 초대 미리보기에서는 가계부 이름 대신 현재 구성원을 보여줘 사용자가 참여 대상을 확인하게 한다.

### 거래 기록

첫 화면에서 수입·지출·이체를 선택하고 금액에 초점을 둔다. 날짜와 실제 구성원은 오늘·본인을 기본값으로 한다. 사람 선택은 `거래 주체`나 `거래한 구성원` 대신 수입 `누가 받았나요?`, 지출 `누가 썼나요?`, 이체 `누가 옮겼나요?`로 묻고 상세에서는 각각 `받은 사람`, `쓴 사람`, `옮긴 사람`으로 표시한다. 다른 멤버 선택 시 프로필 표시와 이름을 함께 보여준다. 작성자는 인증 세션에서 자동 기록하므로 입력 항목으로 노출하지 않는다.

선택한 사람은 해당 수입·지출·이체를 실제로 한 구성원 한 명이다. 공동 선택은 제공하지 않는다. 다른 구성원을 선택해도 현재 로그인한 사용자는 작성자로 별도 기록된다는 점은 상세 화면에서만 보조 정보로 보여주고 입력 흐름을 복잡하게 만들지 않는다.

수입·지출의 필수 필드는 금액, 날짜, 분류, 자산이며 내용은 선택 사항이다. 이체에는 분류가 없고 내용만 선택 입력한다. 이체의 `보내는 자산`과 `받는 자산`에는 같은 가계부의 활성 계좌·적금·주식 계좌를 모두 보여주고, 각 항목에 자산 이름·종류와 `나`·구성원 이름 소유 marker를 표시해 동일한 이름도 구분한다. 이체한 사람 선택은 자산 소유자와 독립적이다. 음수 잔액 계좌도 후보에 포함하며 현금·카드·대출 등 다른 유형은 섞지 않는다. 허용된 세 유형 사이의 납입·인출·자금 이동은 같은 통계 제외 이체를 사용한다. 후보가 두 개 미만이면 필요한 이유를 인라인으로 알리고 저장을 막되 이미 입력한 금액·날짜·주체·내용은 보존한다. 저장 직후 목록에 낙관적 반영할 수 있지만 서버 응답이 실패하면 원래 입력을 보존해 재시도하게 한다.

원화 금액 입력은 일반 텍스트·숫자 필드와 다른 공통 `MoneyField`로 표현한다. 입력과 동시에 천 단위 콤마를 넣고, 우측 정렬한 20–24px semibold tabular 숫자와 오른쪽의 고정 `원` 단위를 56px 입력 안에 배치해 은행 앱처럼 금액을 먼저 읽게 한다. 거래 기록의 금액 입력은 48px·18–20px의 compact 강조를 유지하되 모바일에서는 첫 번째 전체 폭 행으로 두고 날짜는 바로 다음 독립 행에 둔다. 분류·자산도 각각 독립 행으로 이어 사용자가 위에서 아래로 한 번만 훑게 하며, viewport 폭을 채우기 위한 임의의 2열은 만들지 않는다.

모든 `MoneyField`는 숫자·`00`·`000`, 전체 지우기·한 자리 지우기, 더하기·빼기·곱하기·나누기·결과 적용·완료를 가진 공통 계산기를 연다. 음수를 허용하는 기준일 잔액만 부호 전환을 활성화한다. 모바일·설치형 PWA에서는 `inputmode="none"`으로 시스템 가상 키보드를 요청하지 않고 계산기를 safe area 위의 full-width 하단 도구창으로 보여주며, `768px` 이상에서는 같은 DOM을 입력 바로 아래 336px 안팎의 popover로 보여준다. 각 버튼은 44px 이상이고 이름으로 연산 의미를 전달하며 결과·오류를 화면 읽기 도구에 알린다. 하드웨어 키보드와 붙여넣기는 유지한다.

계산기 버튼의 촉각 피드백은 지원 기기에 한해 10ms 진동을 요청한다. 사용자 에이전트나 OS가 진동을 차단하거나 Vibration API가 없으면 아무 효과도 만들지 않으며 별도 권한 prompt나 시각적 대체 animation을 추가하지 않는다. 시스템 키보드의 햅틱 설정을 웹에서 추론하지 않고 iPhone·iPad의 무진동도 정상적인 점진적 지원으로 취급한다.

붙여넣은 콤마·`₩`·`원`은 안전하게 정규화하지만 소수와 다른 문자는 값으로 바꾸지 않는다. 계산도 정수 원 단위만 허용해 0으로 나누기, 나머지가 있는 나눗셈, 범위 초과와 허용되지 않는 음수 결과는 입력 금액을 보존한 채 설명한다. 실제 draft와 API에는 콤마 없는 원 단위 정수만 유지하고, 미완성 두 번째 피연산자·오류·닫기·충돌·viewport 변경으로 사용자가 입력한 금액을 잃지 않는다.

거래 날짜는 중간에 놓인 짧은 native input이 아니라 금액과 같은 전체 폭·48px의 선택 trigger로 표현한다. trigger에는 달력 icon, `2026. 8. 13.` 형식의 현재 선택, 펼침 표시를 한 행에 두고 입력 영역의 좌우선을 맞춘다. 누르면 모바일에서는 safe area 위의 하단 drawer, iPad·데스크톱에서는 trigger 바로 아래의 compact popover에서 월 달력을 연다. 이전·다음 달, 오늘, 날짜 선택, 방향키·Enter·Escape 조작을 제공하고 닫으면 trigger로 focus를 돌려준다. 화면에는 한국식 날짜를 보여도 draft와 서버에는 `YYYY-MM-DD`만 전달하며 viewport 변경·오류·다른 picker 사용 중에도 선택 날짜를 보존한다.

### 자산

신규 등록은 사용자가 자산을 먼저 장부에 올리는 데 집중한다. 모든 자산은 자산 종류, 선택 입력인 자산 이름, `기준일 잔액`과 `잔액 기준일`을 입력하며, 대출은 같은 금액 입력을 `기준일 대출 잔액`으로 부른다. 금액은 선택한 날짜가 시작될 때 실제로 있던 잔액이고 그보다 앞선 기록은 통계에는 남지만 현재 잔액을 바꾸지 않는다는 짧은 도움말을 함께 제공한다. 종류는 `select`가 아니라 모바일에서도 한눈에 비교하고 누를 수 있는 고정 시스템 종류 버튼 그룹으로 제공하고 선택 상태를 `aria-pressed`, 글자 굵기와 색·경계 변화로 함께 표현한다. 이름을 비워 두면 종류 기반 기본명을 쓰고, 소유자 marker·메모는 신규 화면에 노출하지 않은 채 현재 사용자·없음으로 저장한다.

등록 성공 후에는 자산 목록으로 돌아간다. 사용자가 목록에서 해당 자산을 열면 이름, 소유자, 기준일 잔액·잔액 기준일, 메모를 수정할 수 있다. 같은 기본 이름의 활성 자산이 있으면 사용 가능한 가장 작은 숫자 suffix를 붙여 `계좌 2`, `계좌 3`처럼 저장한다. 상세에서 직접 입력한 이름은 종류를 바꿔도 유지하며, 사용자가 이름을 지운 경우에만 현재 종류의 사용 가능한 기본 이름으로 돌아간다. `기타`는 별도의 종류 이름을 요구하지 않는 현금성 자산이고 구체적인 용도는 자산 이름으로 구분한다. `저축` 버튼은 `적금`으로 표시한다.

신용카드는 정산일, 결제 월·일, 결제 계좌를 신규 등록 흐름에 펼치고 모두 필수로 받는다. 체크카드는 `결제 계좌`를 필수로 받는다. 적금은 `자동이체 설정` switch를 기본으로 끄고 계좌·날짜 없이도 등록할 수 있게 한다. 사용자가 switch를 켠 경우에만 `자동이체 계좌`와 `자동이체일`을 함께 펼쳐 모두 필수로 받는다. 이 설정은 자동 실행 정책이 아니라 이후 상세 자동이체 설정의 출금 계좌·달력일 기반값이다. 신용카드 자동 정산은 기본으로 끈 채 저장하고 상세 수정에서 사용자가 켠다. 연결 계좌 후보가 없으면 유형별 draft를 유지하면서 `계좌 등록` 행동을 제공하고 필요한 연결 설정을 완료할 수 없는 이유를 인라인으로 알린다. 이 행동은 새 탭이 아니라 같은 화면의 dialog를 열고, 계좌 생성 성공 즉시 새 계좌를 선택한다. 입력 필드는 모바일 `320–767px`에서 한 열로 읽히게 하고, iPad·데스크톱에서만 정산일과 결제 월·일, 자동이체 계좌와 이체일처럼 짧고 연관된 필드를 병렬 배치한다.

계좌 등록 dialog는 자산 등록 폼을 중첩하지 않고 독립된 form으로 동작한다. 입력은 `계좌 이름 (선택)`, `기준일 잔액`, `잔액 기준일`만 제공하며 오류가 나면 그대로 유지한다. 기준일 잔액은 실제 `0`을 기본 입력하지 않고 빈 입력과 `0` placeholder로 시작하며, 그대로 저장하면 0원으로 처리한다. 0원이 아닌 경우에만 사용자가 값을 입력한다. 모바일·PWA를 포함한 모든 viewport에서 화면 높이를 강제로 채우지 않고 콘텐츠 높이에 맞춰 중앙에 두며, 상하 안전 여백을 남긴 최대 높이를 넘을 때만 dialog 내부를 스크롤한다. 모바일 안전 영역과 iPad·데스크톱의 제한된 읽기 폭을 유지한다. `Escape`와 브라우저 뒤로 가기는 부모 화면이 아니라 dialog를 닫고, 닫힌 뒤 trigger focus를 복원한다. modal focus 범위와 접근 가능한 이름을 제공하며 장식성 카드·중첩 표면은 추가하지 않는다.

신용카드·체크카드·적금의 연결 계좌 select 아래에는 후보 유무와 관계없이 compact한 `계좌 추가` 행동을 둔다. 후보가 없을 때만 저장할 수 없는 이유를 함께 알리고, 후보가 있으면 별도 경고 없이 추가 행동만 제공한다. 생성 성공 뒤 새 계좌가 선택된 사실을 select 값과 focus로 바로 확인할 수 있어야 한다.

신규 등록과 상세 수정 모두 입력 항목 수보다 길고 무거워 보이지 않는 compact form을 사용한다. 자산 종류는 모바일에서 3열, 큰 모바일·태블릿·데스크톱에서 5열을 기본으로 하며 긴 종류명은 버튼 안에서 줄바꿈한다. 상세 수정은 `기본 정보 · 소유 표시 · 시작 금액과 날짜` 같은 당연한 입력 묶음을 별도 단계로 나누지 않고 각 label과 간격만으로 읽는 순서를 만든다. 데스크톱의 넓은 공간도 자동 2열로 채우지 않는다. 같은 결정을 내리는 필드만 한 행에 두고, 필드 의미에 맞춘 비대칭 폭과 독립 행의 최대 너비로 시선 흐름을 만든다. 신용카드·체크카드·적금의 조건부 설정만 짧은 유형별 표지와 한 번의 구분선 아래에 펼치고, 데스크톱의 자산 빠른 이동 영역도 둥근 보조 카드가 아니라 독립된 행 목록으로 구성한다.

음수 기준일 잔액은 별도의 부채 토글 없이 부채로 표시한다. 잔액 기준일 이전 거래도 막지 않고 통계·원장 이력에 표시하되 현재 잔액에는 다시 합산하지 않는다. 소유자 표시는 정보이며 모든 구성원이 수정할 수 있다는 문구를 설정 화면에서 한 번 명확히 안내한다.

활성 자산은 가계부당 50개까지 등록할 수 있다. 자산 화면에 현재 개수와 한도를 표시하고 50개에 도달하면 추가 버튼을 비활성화하면서 보관한 자산은 한도에서 제외된다는 설명을 제공한다. 동시 생성으로 서버가 한도를 거부하면 작성 중 입력을 그대로 보존한다.

새 가계부에는 생성 즉시 0원의 현금·계좌·신용카드·체크카드 행이 보인다. 사용자는 기본 자산을 즉시 열어 수정하거나 `자산 추가`로 더 만든다. 기본 신용카드는 14일 정산·25일 다음 달 결제·자동 정산 끔, 두 카드는 모두 기본 계좌 연결을 상세에서 바꿀 수 있다. `BANK` 종류는 사용자에게 `계좌`, `SAVINGS`는 `적금`으로 표시한다.

자산 첫 화면 상단은 둥근 카드 묶음이 아니라 `순자산 → 총자산·총부채 → 가까운 결제 합계·그다음 결제 합계` 순서로 위계를 만든다. 순자산·총자산·총부채에는 사용 종료 자산의 잔액도 포함하지만, 카드 결제 예정 금액에는 미결제 명세가 있는 활성 카드만 포함한다. 합계의 각 열은 각 카드별 첫 번째·두 번째 결제 예정액을 더한 값이며 하나의 공통 날짜를 뜻하지 않는다.

아래 목록은 `자금 · 카드 · 투자 · 대출 · 보험`의 고정 순서로 모든 viewport에서 한 열로 이어진다. `자금`은 현금·기타·계좌·적금을 함께 읽기 위한 한 단어 화면 표지다. 마이너스 통장은 별도 종류 버튼을 두지 않고 계좌의 signed 잔액과 사용자가 정한 자산 이름으로 표현한다. 그룹명은 14px/20px semibold 본문색, 개수는 11px/16px normal muted 부가정보로 두되 15px semibold 자산 이름과 16px 그룹 합계 금액보다 낮은 시각 위계를 유지한다. 서로 다른 분류가 한 표처럼 붙지 않도록 그룹 사이 여백은 모바일 24px, iPad·태블릿·데스크톱 32px로 둔다. 각 그룹은 전체 폭의 1px 기준선에서 바로 시작하고 header 안쪽 세로 여백으로 표지와 합계를 정렬하며, 그룹 머리 하단과 자산 행의 내부 구분선은 더 옅게 한다. 배경·아이콘·둥근 모서리·그림자는 추가하지 않는다.

`자금` 그룹은 현금·기타·계좌·적금을 함께 보여주고 그룹 `현재 합계`와 각 행 `현재 자산`을 가장 오른쪽 한 열에 정렬한다. 그룹 `현재 합계` 금액은 16px semibold를 유지하고, 개별 자금 행의 `현재 자산` 금액은 14px semibold로 한 단계 낮춰 합계와 항목을 빠르게 구분하게 한다. 값은 signed 현재 잔액 그대로여서 음수 계좌는 `-금액`, 양수는 부호 없는 금액, 0은 muted `0원`이다. 이 그룹에는 별도 `부채` 열이나 절댓값을 사용하지 않는다. 투자·대출·보험의 기존 잔액 의미는 유지한다.

자산 행의 identity는 종류·소유자 전용 고정 열을 만들지 않는다. 자산명은 15px/20px semibold로 먼저 두고 필요한 종류·소유자만 다음 12px/16px normal muted 보조행에 둔다. `계좌`, `계좌 2`처럼 `종류명` 또는 `종류명 + 양의 정수`인 이름은 종류를 반복하지 않고, `월급통장`처럼 custom 이름일 때만 `계좌`를 보조행에 붙인다. 전체 보기에서는 현재 사용자 `나`, 다른 구성원 표시명을 같은 보조행에 붙이지만 구성원 소유자별 보기에서는 선택된 소유자를 반복하지 않는다. 모바일에서는 자산명과 metadata를 말줄임표 없이 자연스럽게 감싸 전체 텍스트를 읽게 하고, iPad 이상에서만 이름과 보조행 각각에 제한적 말줄임을 허용한다. hover로만 새 정보를 노출하지 않고 전체 종류·소유자는 링크의 접근 가능한 이름과 title, 상세 화면에 보존한다.

신용카드 행은 `M월 d일 결제 | M월 d일 결제` 두 열을 사용하고 `부채`, `현재 부채`, `카드 부채`를 표시하지 않는다. 아직 결제되지 않은 실제 명세를 날짜순으로 정렬한 첫 두 날짜와 금액이며, 결제일이 지난 미결제액도 숨기지 않는다. 미결제 명세가 없거나 체크카드이면 가짜 날짜와 `0원 | 0원` 대신 `결제 예정 없음`을 표시한다. 전체 카드 그룹의 `가까운 결제 합계 | 그다음 결제 합계`는 16px semibold, 개별 신용카드 행의 금액은 14px semibold로 두어 합계→항목 위계를 만든다. 480px 미만에서는 자산 정보 다음 행에 두 열을 놓고 그 이상에서는 같은 행에 정렬한다. 컬럼 label은 11px muted, 금액은 우측 정렬 `tabular-nums`와 `whitespace-nowrap`을 사용하고, DOM 순서는 자산 정보→가까운 결제→그다음 결제를 유지한다. 두 열 사이에는 카드 배경·사방 테두리·굵은 divider를 만들지 않는다.

모바일에서 `자금`·투자·대출·보험의 단일 잔액은 이름 오른쪽 끝에 두어 목록 밀도를 유지하고, 480px 미만의 카드만 자산 정보를 첫 행 전체에 둔 뒤 이번 달·다음 달 두 금액 열을 다음 행에 둔다. 480px 이상에서는 자산 정보와 금액 rail을 같은 행에 두되 그룹 머리와 각 행의 금액 right edge를 맞춘다. 일반적인 열에 담을 수 없는 매우 긴 원화 값은 해당 행의 label과 전체 금액을 세로로 적층해 숫자 중간 줄바꿈과 페이지 overflow를 막는다. 데스크톱에서도 자산 그룹 자체를 두 열로 갈라 지그재그 읽기를 만들지 않으며 시계열 데이터가 생기기 전에는 현재 숫자를 반복하는 장식용 차트를 추가하지 않는다.

자산 현황 제목 옆에는 전체 활성 개수·한도만 작은 metadata로 붙이고 새로고침과 자산 추가를 같은 행동 묶음에 둔다. 활성 개수만을 위한 전체 폭 utility 행이나 구분선은 만들지 않는다. 그 아래 `소유자별 보기`는 visible 소제목이나 별도 필터 상자 없이 `전체`, 현재 사용자 이름 `(나)`, 나머지 구성원 이름이 이어지는 text subnav로 둔다. 첫 진입에는 현재 사용자 `(나)`가 선택되어 자신의 자산과 합계를 먼저 보여주며, 사용자가 전체를 선택하면 그 선택을 새로고침 뒤에도 유지한다. 각 항목은 최소 44px hit area, 투명한 배경과 하단선만 사용하며 선택 항목은 `aria-pressed`, forest 하단선, 글자색과 굵기를 함께 바꾼다. 사방 테두리·둥근 segmented control·필터별 visible 개수는 사용하지 않고 결과 개수는 보조기기에만 알린다.

소유자 subnav는 320px부터 같은 DOM의 한 줄을 유지하고 subnav 내부에서만 가로 스크롤한다. 긴 이름도 말줄임표로 숨기지 않으며 버튼 전체를 스크롤해 읽고 선택할 수 있게 한다. subnav 바로 다음에 순자산과 총부채·총자산, 가까운 두 카드 결제 rail을 두고, 정상 화면의 전체 폭 구분선은 요약 하단 한 번만 사용해 `보기 선택 → 해당 숫자 → 자산 행`이 하나의 현황으로 이어지게 한다. 결과가 없으면 큰 중앙 카드·아이콘·반복 자산 추가 행동 없이 왼쪽 정렬 문장과 전체 보기만 요약 위치에 보여준다.

### 자산별 거래 내역

자산 행을 누르면 편집 form이 아니라 해당 자산의 원장을 연다. 모바일 상단 앱 bar에는 자산명, 목록으로 돌아가기, 활성 자산의 우상단에 `기록 추가` + 아이콘과 기어 `자산 편집`을 나란히 둔다. 사용 종료 자산은 `사용 종료`와 잔액·과거 거래를 유지하고 편집 대신 `다시 사용` 진입점을 제공한다.

거래는 최신순 한 열 목록이며 페이지 끝 240px 전후에 다음 cursor를 자동으로 요청하고 명시적 `이전 거래 더 보기` 버튼도 키보드 fallback으로 남긴다. 현재 불러온 모든 page를 합친 뒤 날짜별로 그룹화해 page 경계에서 같은 날짜 제목이 중복되지 않게 한다. 날짜 제목은 연·월·일·요일과 불러온 거래 건수로 한 번만 보이고, 거래마다 구분선과 날짜를 반복하지 않는다. 날짜 머리의 옅은 구분선 하나, 날짜 사이 여백과 목록 왼쪽 12px(태블릿 이상 16px) 들여쓰기로 구분한다. 행에는 내용 또는 분류, 그 자산에서의 signed 증감액, 거래 종류와 필요한 집계 제외 상태를 compact하게 표시한다. 체크카드 거래는 체크카드 원장에서는 사용 기록으로, 연결 계좌 원장에서는 실제 차감 posting으로 모두 찾을 수 있고, 이체는 두 계좌 각각에서 자기 방향의 signed 금액을 보여 준다.

거래 행은 상세를 먼저 연다. 모바일은 이전 목록으로 돌아가는 앱 bar 뒤에 금액·날짜·분류·자산 흐름·실제 돈을 쓴/받은/옮긴 사람·집계 여부·내용을 위에서 아래로 읽고, 데스크톱도 같은 의미를 넓은 한 열에 유지한다. 일반 거래의 `기록 편집`은 상세 제목 오른쪽 아이콘으로 제공하고 `기록 삭제`와 삭제 확인은 편집 화면 하단에서 진행한다(D-075). 카드 구매는 기존 정정·환불 상세로 이어지고 카드 환불·자동 정산은 정확한 상세를 읽되 일반 편집·삭제 행동은 제공하지 않는다. 일반 편집 form과 자산 편집 form은 각각 `/edit` 경로로 분리해 조회와 설정 행동이 섞이지 않게 한다.

### 자산 삭제와 사용 종료

활성 자산 편집의 마지막에는 낮은 위계의 `자산 삭제 또는 사용 종료` 행동을 둔다. `처리 방법 확인`을 누르면 서버의 최신 미리보기를 받아 결과를 설명한다. 최초 금액만 있고 실제 거래 이력이 없으면 `완전 삭제`, 실제 이력이 있으면 `사용 종료`로 표현한다. 내부 `archive` 용어는 사용자에게 노출하지 않는다.

현재 잔액은 `사용 종료 후에도 순자산에 포함됩니다`라고 안내한다. 미결제 카드 명세가 있으면 `남은 명세는 유지되지만 예약 결제와 새 선결제는 중단됩니다`라고 명시한다. 사용 종료 자산은 낮은 위계의 `사용 종료 자산 N개`에서 과거 내역을 확인하고 `다시 사용`할 수 있다.

활성 그룹 아래에는 낮은 위계의 `사용 종료 자산 N개`를 둔다. 목록은 이름·종류·소유자·부호 있는 잔액을 compact 행으로 보여주고 `사용 종료` 상태를 표시한다. 결제 예정 합계에는 섞지 않는다.

사용 종료 자산 상세는 이름·종류·소유자·잔액 기준일·기준일 잔액·현재 잔액·사용 종료일을 읽기 전용으로 제공한다. 과거 거래와 카드 명세는 열 수 있지만 새 거래·새 선결제는 제공하지 않는다. `다시 사용`하면 기존 식별자와 거래를 그대로 유지한다.

삭제·보관 확인은 viewport마다 다른 컴포넌트를 만들지 않고 하나의 shadcn `Dialog` DOM을 재배치한다. 모바일은 좌우 16px을 남긴 거의 전체 폭, iPad·데스크톱은 최대 36rem의 내용 높이 중앙 다이얼로그로 두고 안전 높이를 넘을 때만 본문 내부를 스크롤한다. Escape·시스템 뒤로가기는 다이얼로그만 닫고 트리거로 focus를 돌려보내며 draft와 query 상태를 유지한다.

최종 요청에는 미리보기의 `expectedVersion`과 `previewToken`을 함께 보낸다. `412`이면 최종 행동을 제거하고 `처리 방법이 달라졌어요` 경고에 focus를 옮긴 뒤 `최신 내용 다시 확인`만 제공하며, 새 미리보기를 사용자가 다시 확인하기 전에는 자동 실행하지 않는다. 새 차단 관계가 생긴 `409`, 이미 삭제·보관된 `404`, 오프라인 오류는 서로 다른 문구로 안내한다. 성공하면 활성·보관·전체 자산 목록과 상세를 함께 갱신하고 목록으로 이동한 뒤 실제 결과가 삭제인지 보관인지 알린다.

### 설치형 웹 앱

지원 브라우저에서는 홈 화면 설치 안내를 강요하지 않고 사용자가 기능을 한 번 경험한 뒤 제공한다. 설치 후에는 standalone으로 실행하되 브라우저 버전과 동일한 기능을 유지한다. 오프라인에서는 현재 입력을 보존하고 `연결되면 저장할 수 있어요` 상태를 보여주며 저장 행동을 비활성화한다. 새 버전이 있어도 작성 중 폼을 자동 reload하지 않고 저장 또는 취소 후 갱신하도록 안내한다.

### 카드 결제

카드 구매 행에는 `일시불` 또는 `할부 n/m · 결제 예정` 보조 상태를 표시하되 소비가 아직 통계에 미반영된 것처럼 보이게 하지 않는다. 선결제는 개별 구매를 고치는 행동이 아니라 여러 구매가 묶인 명세의 남은 금액을 줄이는 행동이므로 신용카드 자산 상세를 단일 진입점으로 둔다. 개별 구매 상세에는 선결제 버튼을 반복하지 않고 귀속 명세와 `카드 결제 내역 보기` 링크만 제공한다. 카드 자산 상세의 설정과 결제 내역은 같은 자산 안에 있되 `설정 변경`과 `선결제 기록`을 한 form에 섞지 않는다.

카드 자산 상세 상단은 장식성 카드 없이 가장 가까운 미결제 명세의 `남은 결제`, 결제 예정일, 결제 계좌를 먼저 보여주고 `자동 정산 사용/사용 안 함`과 `자동 정산 설정`을 한 단계 낮은 보조 행으로 둔다. `현재 부채`처럼 자산 현황과 의미가 겹치는 표현은 쓰지 않는다. 그 아래 명세는 결제 예정일 순서의 한 열 목록으로 이어지고 각 명세에 `청구 원금 · 결제 완료 · 남은 결제`를 같은 순서로 정렬한다. `선결제` 행동은 서버가 계산한 선결제 가능 금액이 0원보다 큰 명세에만 제공한다. 완료된 명세는 행동 대신 `남은 결제 0원 · 결제 완료`와 기결제 내역을 그대로 남긴다.

명세 상세의 기결제 내역은 날짜, `선결제/자동 정산`, 출금 계좌, 금액 순서로 보여주며 경제활동 주체는 표시하지 않는다. 수동 선결제의 작성자는 감사 정보가 필요한 상세에서만 낮은 위계로 보여준다. 결제와 선결제에는 `통계에 포함되지 않아요`를 한 번 명시해 일반 소비와 구분한다. 자동 정산 상태는 raw enum과 내부 오류를 노출하지 않고 `자동 정산 예정`, `처리 중`, `자동 정산 완료`, `다시 시도 예정`처럼 사용자가 다음 상태를 이해할 수 있는 문구로 변환한다. 결제 예정일이 지난 catch-up도 별도 기능명이나 실패로 부르지 않고 서버 상태가 재시도 대상일 때만 `예정일이 지났어요 · 자동 정산 다시 시도 예정`으로 안내하며, 날짜만 보고 클라이언트가 처리 실패를 추론하지 않는다.

`선결제`는 modal이나 bottom sheet가 아니라 카드·명세 맥락을 유지하는 인라인 또는 독립 화면에서 `입력 → 서버 미리보기 → 기록` 순서로 진행한다. 남은 결제액을 금액 기본값으로 제안해 전액 선결제는 한 번에 끝내되 사용자가 원 단위 일부 금액으로 바꿀 수 있고, 완료 후 같은 명세에 남아 복수 선결제를 이어갈 수 있다. 결제 계좌는 해당 카드에 설정된 계좌를 읽기 전용 자금 출처로 보여준다. 적용일은 사용자가 고르는 입력이 아니라 서버가 `Asia/Seoul`의 오늘로 확정해 미리보기에 읽기 전용으로 보여준다. 미리보기에는 현재 남은 결제, 이번 선결제, 선결제 후 남은 결제, 출금 계좌의 현재 잔액과 기록 후 잔액, 적용일을 보여주고 계좌가 음수가 되어도 오류나 경고색 대신 signed 결과와 `잔액이 부족해도 전액 기록돼요` 설명을 사용한다. 최종 행동 문구는 외부 카드사에 결제를 요청하는 것처럼 보이는 `결제하기`가 아니라 `선결제 기록`으로 한다.

입력을 바꾸면 기존 미리보기는 즉시 폐기하고 apply를 막는다. preview·apply 요청 중에는 대상 명세 version, 금액, 서버 확정 적용일, 결제 계좌를 잠가 서로 다른 계산이 섞이지 않게 한다. 두 세션 중 먼저 결제한 세션 때문에 명세 version이나 남은 금액이 달라져 `412`가 오면 내 금액 draft를 보존하고 오래된 미리보기를 폐기한다. 최신 남은 금액과 내 입력을 함께 보여준 뒤 `최신값으로 다시 계산`을 거쳐야만 기록할 수 있다. apply 중에는 최종 버튼을 비활성화하고 같은 idempotency key의 재시도는 한 결제로 취급한다. 동일 요청이 이미 처리 중이면 중복 실패를 만들지 않고 `같은 선결제를 처리 중이에요. 최신 내역을 확인해 주세요`와 재조회를 제공한다.

0원, 음수, 서버가 제시한 남은 금액 초과는 인라인 금액 오류로 미리보기를 막는다. 직접 URL로 이미 결제 완료된 명세에 들어오거나 미리보기 사이 잔액이 0원이 되면 빈 form을 보여주지 않고 `결제가 완료된 명세예요`와 기결제 내역으로 돌아가는 행동을 제공한다. 자동 정산 설정 변경은 자산 version을 쓰는 별도 저장이며 기존 결제 출처와 내역을 다시 쓰지 않는다.

카드 명세 목록은 같은 DOM을 container query로 재배치한다. 320~390px에서는 `예정일·상태` 다음 줄에 세 금액을 동일한 3열로 놓고, `선결제`는 다음 줄의 명확한 44px 행동으로 둔다. iPad 세로에서는 명세 정보와 세 금액을 두 줄 grid로, iPad 가로·데스크톱에서는 `예정일·상태 | 청구 원금 | 결제 완료 | 남은 결제 | 행동`의 한 행 grid로 맞춘다. 기결제 내역도 모바일에서는 날짜·종류와 계좌·금액의 두 줄, 넓은 화면에서는 한 행으로 바꾸며 가로 스크롤과 사방 테두리 표를 만들지 않는다. 금액은 `tabular-nums`, 우측 정렬, 중간 줄바꿈 금지를 유지한다.

각 명세 영역은 결제 예정일과 상태를 포함한 접근 가능한 이름을 가지며 `선결제` 버튼의 접근 가능한 이름에는 대상 결제 예정일을 포함한다. 미리보기 완료 시 제목으로 focus를 옮기고, 오류·`412` 요약은 focus 가능한 `role="alert"`, 처리 상태 변화는 `aria-live="polite"`로 알린다. 상태는 색만으로 구분하지 않고 문구를 함께 제공한다. 200% 확대와 320px에서 가로 overflow가 없어야 하고, viewport 회전·breakpoint 변경 뒤에도 입력, 미리보기 폐기 여부, focus가 유지되어야 한다.

카드 결제 흐름은 다음을 자동 검수한다.

- 카드 구매 상세에는 명세 링크만 있고 카드 자산 상세의 해당 명세에서만 선결제를 시작할 수 있다.
- 같은 명세에 부분 선결제를 두 번 기록하면 각 결제 내역과 감소한 남은 결제가 보이며, 마지막 전액 기록 뒤 선결제 행동이 `결제 완료`로 바뀐다.
- 출금 계좌 잔액보다 큰 금액도 preview와 apply가 성공하고 기록 후 signed 음수 잔액이 정확히 보인다.
- 자동 정산 사용 여부, 출금 계좌, 예정일, 완료·재시도 상태가 명세 금액과 섞이지 않고 동일한 서버 상태를 나타낸다.
- 두 세션이 같은 version으로 preview한 뒤 한쪽이 먼저 기록하면 다른 쪽 apply는 `412`로 전체 거부되고 draft를 보존한 재계산 없이는 재적용할 수 없다.
- apply 버튼 연타와 네트워크 재시도가 결제 한 건만 만들고 처리 중·성공 뒤 명세와 출금 계좌 query를 최신화한다.
- `390×844`, `768×1024`, `1180×820`, 200% 확대에서 같은 정보와 행동을 유지하고 페이지 가로 overflow, focus 유실, 44px 미만 행동이 없다.
- 키보드와 화면 읽기 도구만으로 명세 선택, 금액 입력, 미리보기, `412` 복구, 최종 기록과 결과 확인을 끝낼 수 있다.

카드 결제에는 사람을 거래 주체로 표시하지 않고 `어느 계좌에서 빠졌는지`를 우선한다. 결제 계좌 잔액이 음수가 되어도 정산은 전액 기록되며, 음수 잔액을 오류 상태로 보이지 않는다. 결제 예정일은 비영업일이면 다음 한국 영업일로 순연된다고 안내한다.

카드 구매 상세에는 `기록 정정`과 `환불 처리`를 서로 다른 행동으로 보여준다. 기록 정정은 원 결제일의 기록을 고친다는 점과 소급 영향을 확인시키고, 환불 처리는 실제 환불일과 원 결제 계좌로 돌아갈 금액을 저장 전에 보여준다. 저장 후에는 사용자가 별도 보정 거래를 만들지 않아도 카드·결제 계좌 원장이 자동으로 일치해야 한다.

일별 원장의 카드 구매와 `환불 +금액` 행은 모두 같은 원 구매 상세로 연결한다. 기록 정정 폼의 주 행동은 처음부터 `정정 저장`이며, 누르면 서버가 영향을 계산한 뒤 `정정 내용을 저장할까요?` 확인 dialog를 열어 바뀐 필드와 미결제 감소·계좌별 장부 반환을 보여준다. dialog의 `저장`만 실제 반영하고 `취소`는 dialog만 닫아 입력 draft를 그대로 유지한다. 별도의 인라인 `변경 내용 확인 → 정정 적용` 단계는 두지 않는다. 환불은 `환불 내용 확인`으로 서버 계산 결과를 먼저 보여주는 기존 흐름을 유지한다. preview·apply 요청 중에는 확인 대상 draft를 잠시 잠그고 응답과 다른 입력이 혼합되지 않게 한다. `412`에서는 draft를 보존하고 기존 preview를 폐기한 뒤 서버 최신값과 내 입력을 비교해 `최신값으로 영향 다시 계산`을 거쳐야만 apply할 수 있다. 환불일에 다른 지출이 없어 일별 지출 합계가 음수가 되더라도 달력에 `환불 +금액`을 생략하지 않는다. 환불은 수입이 아니므로 수입 색을 쓰지 않고 문구와 금액 부호로 의미를 함께 전달한다.

사용 종료 자산 상세는 신규 선택과 자동 결제에서 제외된다는 결과를 설명하고 `다시 사용` 확인 dialog를 제공한다. 선결제 행에는 `선결제 취소`, 자동 정산 행에는 `자동 정산 삭제`를 제공하며 확인 dialog에서 결제 계좌 복원과 카드 미결제 증가를 함께 설명한다. 자동 정산 삭제에는 같은 명세가 자동으로 다시 정산되지 않는 결과도 명시한다.

### 분류와 삭제

공동 분류 관리는 설정의 독립 `분류 설정` 화면에서 수입·지출을 버튼으로 전환하고 현재 방향의 분류를 compact 버튼 모음으로 제공한다. 모바일 320px부터 가용 폭에 맞춰 최소 112px·44px 높이의 열을 자동 배치하고, iPad·데스크톱에서도 같은 DOM을 재배치한다. 각 버튼은 이름만 우선해 보여주며 긴 이름은 최대 두 줄로 제한하고 전체 이름은 접근 가능한 이름·`title`·선택 관리영역에서 제공한다. 선택 상태는 `aria-pressed`와 색 이외의 테두리·굵기를 함께 사용한다.

분류마다 이름 선택 영역과 분리된 44px 순서 이동 핸들을 왼쪽에 둔다. 마우스·펜은 핸들을 끌고, 터치는 핸들에서만 드래그해 목록 스크롤과 충돌하지 않으며, 키보드는 핸들에서 스페이스로 잡고 방향키로 이동한 뒤 다시 스페이스로 놓는다. 이동 중에는 원래 compact grid를 유지하고 과장된 카드 overlay를 만들지 않는다. 저장 성공을 짧게 알리고 공동 변경 충돌이면 이전 낙관적 이동을 확정하지 않은 채 최신 순서를 불러와 다시 이동하도록 안내한다.

분류 버튼을 선택하면 그 분류 하나의 전체 이름, 연결 거래 수, 이름 수정과 삭제 행동을 버튼 모음 아래에 보여주고, 넓은 화면에서는 얇은 세로 구분선 오른쪽에 둔다. 선택하지 않은 분류의 수정·삭제 아이콘과 거래 수를 반복 노출하지 않는다. 기본 `기타`는 선택과 이름 변경이 가능하지만 삭제 행동은 노출하지 않고 fallback 용도를 안내한다. 분류 삭제 확인에는 실제 연결 건수와 같은 방향의 `기타`로 이동함을 명시하고 완료 후 이동 건수·기간을 알린다.

거래 기록에서 분류 trigger를 누르면 모바일은 safe area 위의 하단 drawer, iPad·데스크톱은 compact dialog로 같은 picker를 연다. 분류는 최소 44px의 compact 버튼 grid로 표시하며 현재 선택은 `aria-pressed`, check, 경계와 굵기로 함께 나타낸다. 목록의 마지막은 `항목 추가` 버튼이고, 누르면 같은 overlay 안에서 공동 분류 이름 입력과 `목록으로 · 추가` 행동을 보여준다. 성공하면 새 항목을 선택하고 overlay를 닫으며 금액·날짜·자산·사람·내용 draft는 그대로 둔다. 중복·서버 오류·오프라인에서는 이름 입력과 overlay를 유지하고, 취소·`Escape`·바깥 영역 선택 뒤에는 분류 trigger로 focus를 복구한다.

거래·카드 정정·자산 설정의 자산 field는 이름만 나열하는 select를 사용하지 않는다. trigger에는 선택한 자산의 종류 icon, 이름, 종류·소유자 아바타, 잔액을 두 줄 안에서 보여 주고 신용카드는 잔액 자리에 가장 이른 미결제 결제 예정액을 `결제 예정`으로 표시한다. 모바일은 화면 아래에 붙는 drawer, iPad·데스크톱은 trigger에 붙는 popover로 같은 목록을 열며, overlay 제목은 `결제 자산 선택`, `보내는 자산 선택`처럼 field 맥락을 명시한다. 모바일 drawer와 iPad·데스크톱 popover는 `전체`에서 자금·카드 등으로 필터를 바꾸거나 모든 자산 보기를 전환해도 외곽 높이와 위쪽 위치가 바뀌지 않고 결과 목록만 내부에서 교체·스크롤된다. 데스크톱은 화면 기준으로 trigger에 붙여 배치하고 높이를 화면의 60%와 30rem 중 작은 값으로 유지하되 실제 남은 공간을 넘지 않게 제한한다. 처음 열면 현재 사용자의 개인 소유 자산만 보이고 우상단 `모든 자산 보기` switch를 켜야 다른 구성원 자산이 나타난다. 닫았다 다시 열면 switch는 꺼진 기본값으로 돌아가되, 편집 draft에 이미 담긴 다른 구성원 자산을 임의로 교체하거나 지우지 않는다.

여러 종류가 섞인 후보는 `전체 · 자금 · 카드 · 투자 · 대출 · 보험` compact 필터로 좁히고 각 그룹은 작은 제목과 개수 뒤에 320px 한 열, 충분한 폭 두 열의 64px 내외 항목을 배치한다. 선택 항목은 check·경계·색·`aria-pressed`를 함께 사용하고 owner marker는 `나 · 구성원 이름`으로 표시한다. 계좌 전용·신용카드 전용 후보는 불필요한 종류 필터를 숨긴다. 목록 길이는 최대 자산 50개 경계 안에서 내부 스크롤하고 페이지 전체를 가로 또는 세로로 밀지 않으며, Escape·바깥 영역·닫기 후 trigger에 focus를 복구한다.

거래 주체는 native select나 사람 목록 overlay 대신 현재 구성원이 기본 선택된 compact person radio group으로 고른다. 각 option은 한 글자 식별자, 전체 표시명, 현재 사용자의 `나` 표식과 명시적인 radio 상태를 한 줄에 두고 전체 영역을 눌러 선택할 수 있게 한다. 후보는 모바일부터 최소 44px 조작 영역을 유지하며 가용 폭에 따라 자동 줄바꿈하고, 선택은 색뿐 아니라 radio·경계·배경·굵기로 함께 구분한다. 거래 종류가 바뀌면 질문만 `누가 받았나요? · 누가 썼나요? · 누가 옮겼나요?`로 바꾸고 같은 선택과 다른 draft를 보존한다.

자산 소유자 선택도 같은 compact person radio group을 사용한다. 자산 소유자 subnav·자산 행, 일별 거래 행·거래 상세·입력 요약, 통계의 구성원·소유자 필터에는 동일한 구성원 avatar를 이름 옆에 둔다. 같은 구성원은 화면마다 같은 색과 첫 글자를 사용하고 현재 사용자는 `나`를 함께 표시한다. 작은 avatar는 부가 식별 수단이므로 자산명·내용·금액보다 시각적으로 크거나 단독 label이 되지 않는다.

가계부 전체 삭제는 설정 맨 아래의 구분선 뒤 `파괴적 작업`에만 둔다. 첫 행동은 바로 삭제하지 않고 하나의 modal dialog를 열며, 가계부의 모든 구성원·자산·기록·초대가 함께 영구 삭제되고 구성원 계정과 로그인은 유지된다는 영향을 먼저 설명한다. 사용자가 `가계부 삭제`를 정확히 직접 입력해야 최종 파괴 버튼이 활성화된다. `412`이면 입력을 보존하고 dialog 제목으로 focus를 옮겨 다른 변경이 있었음을 알린 뒤 최신 가계부 정보를 다시 불러와야 하며 자동 재시도하지 않는다. 성공하면 dialog를 닫고 가계부 시작·초대 코드 화면으로 이동한다.

일반 거래 행은 상세·수정 화면으로 이어진다. 유형은 읽기 전용이고 금액·날짜·분류·자산·거래 주체·내용만 고친다. 일반 지출의 결제 자산을 신용카드로 고르면 같은 화면에 `할부 개월`을 즉시 보여주고 기본값 1개월을 사용한다. 저장 성공 뒤부터 해당 행은 카드 구매 상세로 연결하고 이후 변경은 `기록 정정`·`환불 처리`에서 하도록 한다. 삭제 전에는 잔액과 달력 합계가 함께 바뀐다는 짧은 확인을 보여준다. 이미 생성된 신용카드 구매에는 일반 수정·삭제 대신 `기록 정정`·`환불 처리` 진입점만 제공하며, 시스템 거래는 읽기 전용으로 표시한다.

수입·지출 기록에는 공통 `Switch`로 각각 `수입에 포함하지 않기`·`지출에 포함하지 않기`를 제공하고 기본은 끈 상태다. 바로 아래에 `자산 잔액은 바뀌지만 달력과 통계 합계에는 반영하지 않아요.`를 짧게 설명하며 이체에는 노출하지 않는다. 제외된 기록은 월간 달력 합계와 통계에서 사라지지만 일별 원장에는 `집계 제외` 보조 표식을 남기고 금액·자산 흐름은 그대로 보여준다. 일반 거래 수정, 카드 구매 정정과 환불 폼에서도 같은 의미와 상태를 유지하고 viewport 변경·preview·충돌로 switch draft를 초기화하지 않는다. 새 카드 환불의 기본 상태는 원 구매를 이어받되 환불별로 변경할 수 있다.

지출 입력과 수정에는 `대표로 결제했어요` switch를 두고 켠 경우 실제 금액 바로 뒤의 흐름에서 `지출로 반영할 금액`을 입력한다. 설명은 자산에서 실제 결제액이 빠지고 달력·통계에는 내 부담액만 반영된다는 결과를 직접 말한다. 0원도 허용하고 실제 결제액 초과는 인라인 오류로 막으며, 데스크톱 요약과 거래 상세에는 실제 금액과 다른 경우에만 대표 결제·지출 반영액을 함께 보여준다. 카드 구매 정정은 같은 입력을 유지하고, 대표 결제 카드 환불에는 남은 지출 반영액 안에서 `지출에서 차감할 금액`을 별도로 입력한다.

## 공동 편집과 최신값 확인

- 저장 성공 응답으로 현재 작성 세션의 관련 데이터만 갱신한다.
- 다른 멤버의 변경은 화면 진입, 브라우저 탭 재집중, 사용자의 새로고침에서 확인한다.
- 편집 시작 때 읽은 version과 저장 시점 version이 다르면 `412` 충돌로 저장을 막고 어떤 필드도 자동 병합하지 않는다.
- 충돌 화면은 서버 최신값과 보존한 내 입력을 비교해 `최신값에 내 입력 다시 적용` 또는 `취소`를 선택하게 한다.
- 연결 중단 시 읽기는 유지하고 쓰기 전에 오프라인 상태를 명확히 알린다.
- 다른 사용자가 조회 중인 거래나 자산을 삭제한 사실을 재조회 또는 저장 응답에서 확인하면 상세 화면을 닫고 목록 복귀를 한 번만 알린다. 편집 중이라면 draft를 지우지 않고 입력 복사, 새 항목으로 저장, 저장 없이 목록 복귀를 선택하게 한다.

비동기 상태는 `첫 로딩`, `백그라운드 갱신`, `mutation 저장 중`, `오프라인 stale`, `재연결`, `403`, `409/412 충돌`, `원격 삭제`, `복구 불가능 오류`로 구분한다. 전체 화면 skeleton은 첫 로딩에만 사용하고 백그라운드 갱신으로 기존 데이터를 가리지 않는다.

## 테마와 지원 브라우저

테마 선택은 설정 화면의 `기기 설정 · 라이트 · 다크` 세 가지다. 첫 방문은 `prefers-color-scheme`을 따르고 사용자가 바꾸면 해당 기기의 local storage에만 기억한다. 앱이 그려지기 전에 저장된 선택을 적용해 밝은 화면이 잠깐 번쩍이지 않게 하며, 서버 계정 설정으로 동기화하지 않는다. 로그인·온보딩·앱 상단과 sidebar에는 테마 전환 버튼을 반복 노출하지 않는다.

Chromium 모바일·데스크톱, Edge, macOS/iOS/iPad Safari를 공식 지원하고 Firefox는 핵심 smoke 범위로 둔다. 테마별 로고·명암·focus ring과 200% 확대를 공식 브라우저에서 검수한다.

통계의 각 분류 금액 행은 최소 44px 선택 영역을 가진 버튼이며 선택하면 해당 월·분류와 현재 통계 필터에 포함된 거래 내역을 연다. 모바일은 전체 화면 dialog, iPad·데스크톱은 제한된 dialog로 같은 날짜·내용·자산·사람·signed 금액 목록을 보여주고 각 행은 기존 거래 상세로 이어진다. 집계 제외 거래나 다른 달·분류 거래를 섞지 않으며 다음 cursor가 있을 때만 `거래 더 보기`를 제공한다.
| 필터 | 동일 filter dialog를 하단 sheet처럼 정렬 | 동일 dialog를 폭 제한 panel로 정렬 | 동일 dialog를 폭 제한 panel로 정렬 |

모바일 push형 상세·수정 화면은 전체 폭 `돌아가기` 행을 본문에 반복하지 않고, safe area를 반영한 sticky 상단 바에 icon 뒤로가기·현재 화면 `h1`을 한 줄로 둔다. 새 거래 기록은 하단 dock의 최상위 탭이므로 sticky 상단 바와 `가계부로 돌아가기`를 모두 두지 않고 safe area 다음의 본문 `h1`부터 시작한다. 거래 수정은 원장 행에서 진입하는 push 화면이므로 모바일 sticky 상단 바의 icon 뒤로가기를 유지하되 본문에는 복귀 링크를 반복하지 않는다. 하단 dock은 왼·오른쪽·하단 모서리에서 12px 이상과 safe area를 띄우고 20~24px radius의 단일 불투명 표면과 최소한의 그림자만 사용한다. glassmorphism과 tab별 장식 카드는 사용하지 않는다.

하단 dock·태블릿 rail·상단 내비게이션에서 직접 여는 `자산 현황 · 월간 통계 · 가계부 설정`의 대제목은 같은 24px semibold 위계로 시작한다. 홈은 휴대폰 공간을 달력에 우선 배정해 시각적 대제목을 생략하되 접근 가능한 `h1`은 유지하고, `768px` 이상에서는 다른 최상위 화면과 같은 24px `가계부` 제목을 표시한다. 제목 옆 개수와 행동은 제목 크기를 바꾸지 않고 별도 보조 위계로 둔다.

모바일 달력은 화면 가장자리에 붙이지 않는다. 320px에서는 좌우 4px, 360px 이상에서는 8px, 390px 이상에서는 12px의 바깥 여백을 두며 480px 이상은 공통 페이지 여백을 따른다. 날짜 칸 내부는 좌우 3–4px·위아래 12px을 확보하고 768px 이상은 좌우 8px을 사용한다. 7개 열과 금액·건수는 가로 스크롤이나 잘림 없이 유지한다. 좁은 화면에서 표의 열을 단순히 숨겨 의미를 잃게 하지 않고 의미를 보존한 compact row로 재구성한다. 축약한 금액과 잘린 이름의 전체 값은 상세와 접근 가능한 이름에서 제공한다. 파괴적 행동은 swipe·hover에만 숨기지 않는다.

모바일 Sheet와 고정 행동은 `safe-area-inset-*` 네 방향과 동적 viewport 높이를 반영한다. iPad의 touch·keyboard·trackpad를 모두 고려하고 hover 없이 모든 기능을 사용할 수 있어야 한다. resize와 회전은 route, 가계부, 월·날짜, 필터, 선택 상세, scroll, focus, 작성 중 draft를 보존하며 UI 형태가 Sheet에서 panel로 바뀌어도 폼과 TanStack Query 상태를 재마운트하거나 초기화하지 않는다.

| 충돌·원격 삭제 | AlertDialog가 아닌 보존 가능한 conflict panel |

공통 primitive는 `components/ui`에서만 HTML control을 소유하고 기능 화면은 이를 조합한다. shadcn 최신이라는 이유만으로 custom Select나 Combobox를 일괄 적용하지 않고 후보 수, 검색 필요성, 모바일 입력 비용을 기준으로 고른다. Overlay는 Base UI의 focus 관리와 접근 가능한 Title·Description을 사용하고, 돈독의 44px touch target·4~6px control radius·최대 8px overlay radius를 토큰으로 덧입힌다.

모든 기능 handoff는 API 상태에서 TanStack Query의 `initial/pending/success/error/stale/fetching`과 화면 상태로 이어지는 전이표를 포함한다. optimistic update를 사용하는 mutation은 rollback 데이터와 사용자 입력 보존 위치를 명시한다.

## 문장과 피드백

짧고 구체적인 존댓말을 쓴다. `실패했습니다` 대신 `거래를 저장하지 못했어요. 입력은 그대로 두었습니다.`처럼 결과와 다음 행동을 알려준다. 장난스러운 축하 문구, 부부 관계를 가정하는 호칭, 소비를 평가하는 표현을 쓰지 않는다.

## UX/UI ↔ Frontend 협업 규칙

각 기능은 다음 순서로 넘긴다.

1. UX/UI가 목적, 사용자 흐름, 정보 우선순위, 모든 상태와 모바일·iPad 세로/가로·데스크톱 동작을 문서화한다.
2. Frontend가 shadcn 재사용 가능성, 토큰, 접근성, 서버 계약과 TanStack Query 상태 모델을 검토한다.
3. 차이는 코딩 전에 문서에서 합의하고 공통 컴포넌트와 기능 전용 컴포넌트 경계를 기록한다.
4. Frontend 구현 후 UX/UI가 대표 viewport와 breakpoint 양쪽 경계에서 실제 브라우저를 검수한다.
5. QC가 합의된 접근 가능한 이름, 사용자 결과, 회전·resize 상태 보존을 Playwright 인수 조건으로 고정한다.

거래 입력의 반복 비용을 줄이기 위해, 현재 사용자가 경제활동 주체인 마지막 지출의 결제 자산을 다음 새 지출의 기본값으로 사용한다. 다른 구성원의 지출을 대신 기록하거나 수입·이체에 사용한 자산은 이 기본값을 바꾸지 않으며, 날짜 상세·자산 원장처럼 진입 맥락이 특정 자산을 지정한 경우에는 해당 맥락을 우선한다. 기억한 자산을 더 이상 선택할 수 없으면 자동 선택하지 않아 사용자가 보관 자산에 잘못 기록하지 않게 한다.

새 거래의 날짜는 로그인한 입력자가 마지막으로 신규 저장에 성공한 거래일을 사용한다(D-071). 일반 기록과 자산 원장의 빠른 기록에 동일하게 적용하고 달력에서 명시적으로 고른 날짜·전달받은 초안·기존 거래 편집 날짜를 우선한다. 날짜가 더 과거여도 마지막 저장을 기억하며 다른 사람의 거래를 대신 입력한 경우에도 로그인한 입력자 기준이다. 수정·삭제·저장 실패·취소는 기본값을 바꾸지 않는다. 날짜 선호값은 가계부·구성원별 localStorage에 저장하고 없거나 사용할 수 없으면 서울 기준 오늘로 시작한다. 폼 진입 시에만 적용하므로 다른 탭의 저장·focus·resize가 작성 중 날짜를 덮지 않는다. 웹·PWA 모두 같은 규칙이며 분리된 저장 공간에서는 각각 기억한다.

기능별 인수 항목에는 최소한 다음이 포함된다.

- 정상, 로딩, 빈 상태, 오류, 권한과 무관한 비활성, 오프라인, 재연결, 동시 수정 충돌
- 키보드 순서, 접근 가능한 이름, 오류 연결, 포커스 복구
- 실제 긴 이름·큰 금액·N명 멤버·한글 줄바꿈
- 터치 목표, safe area, 대표 viewport와 breakpoint 경계의 가로 overflow 여부
- 회전·resize 전후 draft·필터·focus·scroll·서버 상태 보존
- 서버 성공·실패 시 TanStack Query 캐시와 사용자 입력 보존 방식

회원가입·이메일 인증·로그인 첫 화면이 구현되었으며 이 문서는 이후 화면에도 적용하는 구현 계약이다. 각 화면은 UX/UI 검수와 Frontend 수정, 대표 viewport 브라우저 검증이 끝나야 완료로 처리한다.

### 카드 대금 결제 기록

월간 달력은 카드 정산·선결제를 수입·지출과 구분한 `카드결제` 금액으로 표시한다. 좁은 셀은 금액을 축약하고 접근 가능한 날짜 이름·title에는 정확한 원 금액을 제공한다. 카드결제만 있는 날도 기록이 있는 날짜로 안내하며 날짜 상세와 일별 목록에서 이체 기록을 열 수 있다. `나`·구성원·`모두` 필터는 결제 당시 카드 소유자를 기준으로 적용한다. 상세는 `카드 명의자`와 작성자를 분리해 보여주고 월 수입·지출 합계에는 결제 금액을 더하지 않는다.

### 자산 상세의 미결제 내역

신용카드 자산 상세의 거래 내역 바로 위에 `미결제 내역` 섹션을 둔다. 명세별 예정일(지난 날짜도 그대로), 남은 금액, 청구·기결제 금액과 `명세 보기`·`결제하기`를 제공한다. 완료된 명세는 이 섹션에서 제거하고 원장의 결제 이체로 이어진다. 빈 상태·로딩·실패·추가 페이지를 별도로 안내한다.

`결제하기`는 기존 명세 상세를 읽어 결제 계좌와 남은 전액을 보여주는 dialog를 열며 `결제일` 날짜 선택기를 제공한다. 기본값은 서울 기준 오늘이며 실제 출금일을 선택한 뒤 `전액 결제 기록`으로 해당 날짜의 장부 이체를 만든다. 처리 중·결과가 불명확한 재시도에는 날짜를 고정하고 충돌 후 최신 내용 확인·회전에도 날짜 draft를 보존한다. 실제 은행 요청과 구분해서 설명한다. 자동 정산을 끈 카드와 결제일 이후에도 사용할 수 있고, 사용 종료 카드는 다시 사용하기 전까지 버튼을 비활성화한다. 충돌이면 최신 내용을 사용자가 확인하기 전까지 결제를 막고, 네트워크 실패 재시도는 동일 요청 키를 재사용한다. 같은 화면 DOM과 query 상태를 모바일·태블릿·데스크톱에서 유지한다.

결제일이 지난 결제 완료 명세에 사용을 추가해 다시 미결제가 생기면 `결제 후 사용 내역이 추가됐어요`와 추가분의 수동 결제 안내를 미결제 행과 명세 요약에 표시한다. 청구 전체·기결제·남은 금액을 함께 보여 기존 결제가 취소되거나 바뀐 것으로 오해하지 않게 한다. 추가분을 전액 결제하면 안내를 숨기고 별도 결제 이력으로 남긴다.


## 이체 목적과 자산 형성 통계 (D-068)

이체 폼의 보내는·받는 자산 다음에 이체 목적 5개를 한 DOM의 버튼 그룹으로 표시한다. 초기 목적은 자산 조합으로 제안하고 직접 고른 목적은 자산 변경·회전·충돌 때 보존한다. 상세·원장에 목적을 표시한다. 통계는 보기 탭 없는 통합 화면으로 제공하며 총 사용액은 소비+납입, 적금·투자는 납입/회수/순납입을 정확한 원 금액과 12개월 목록으로 표시한다. 총 사용액에서 회수를 차감하지 않음을 안내한다. 기존 소비 분류 상세 탐색과 홈 달력의 소비 의미는 유지한다.

## D-069 카드 전용 상세 결제

자산에서 신용카드를 열면 카드 대금 요약 머리 오른쪽에 `대금 결제` 링크를 제공한다. 기록 추가는 자산 설정 옆의 44px `+` 아이콘으로 제공한다. 버튼을 누르면 별도 결제 페이지로 이동하고 카드 자산으로 돌아갈 수 있다. 결제 페이지는 카드 이름과 내역 선택 결제·부분 금액 결제 탭, 미결제 합계·최근 정산일, 출금 계좌·실제 결제일을 보여준다. 선택 탭은 사용일·내용·할부 회차·결제 예정일·남은 금액·체크박스를 행으로 표시한다. 기본 체크는 최근 정산일까지 마감된 미결제 항목 전체이며 아직 로드하지 않은 항목도 합계에 포함한다. 미래 회차는 수동 선택할 수 있다. 부분 탭은 총 미결제액과 금액 입력, 오래된 결제 예정일부터 반영한다는 안내를 제공한다. 탭 전환·회전·focus 재조회는 draft를 유지하고 충돌 시 최신 내역 확인 행동을 제공한다. 로딩·빈 상태·실패·오프라인·사용 종료 상태를 인라인으로 표시한다. 결제 이력과 거래 내역은 유지하며 자동 정산 설정을 노출하지 않는다.

## D-075 거래 상세 관리 도구

수입·지출·이체·카드 구매·카드 결제 상세는 공통 TransactionDetailLayout과 label/value 행을 사용한다. 제목 오른쪽의 44px 아이콘으로 편집·정정·환불에 진입하며 aria-label과 title로 행동을 식별한다. 모바일 sticky 상단 바에도 같은 순서로 표시한다. 카드 환불 기록은 원 구매 보기 아이콘을 제공한다. 금액·내용을 상단에 한 번 표시하고 상세 하단의 큰 관리 제목과 행동별 설명 행은 제거한다. 삭제는 일반 편집 화면 하단의 기존 확인 흐름에서만 제공하고 카드 결제 취소도 편집 화면 하단에 둔다.

### 자산 거래 검색·필터

거래 내역 제목은 14px이며 최신순 고정 문구를 두지 않는다. 오른쪽에 44px 검색·필터 아이콘을 배치한다. 검색 입력은 내용·분류 대상으로 제출 시 적용하며 필터 아이콘 아래 한 줄의 compact 도구에서 종류·구성원은 즉시 선택하고 기간 버튼의 작은 비모달 popover에서 시작일·종료일(양 끝 포함)을 적용한다. 초기화는 아이콘으로 제공하고 320px에서도 도구 전체가 가로 스크롤 없이 들어간다. 적용 조건 요약·개수 배지·모달은 두지 않고 URL로 복귀 상태를 유지한다. 조건 변경 시 cursor는 새로 시작하며 전체 자산 이력에서 조회한다. 필터 결과의 거래 후 잔액은 표시하지 않는다. 날짜별 옅은 구분선과 들여쓰기는 공통 컴포넌트를 유지한다. 카드 대금에서는 가장 가까운 결제 금액을 24–30px, 결제일을 14px로 표시하고 같은 줄에 대금 결제 버튼을 둔다. 다음 결제는 하단 보조 행으로 구분한다.

### 공통 거래 내역

홈 일별·자산·카드 내역은 TransactionHistory의 검색·필터·상태·날짜 그룹을 함께 사용한다. 날짜 머리는 불투명 배경의 기본 sticky로 자연스럽게 교체되며 공통 AppShell의 모바일 상단 바 offset을 따른다. 홈에서 검색어·종류·기간을 적용하면 별도 기간 또는 전체 기간을 조회한다. 기본 월간 조회 및 달력 요약은 유지한다. 상단 구성원 선택은 월간 달력과 일별 보기에서 같은 위치에 항상 표시하며, 보기 전환과 공통 인라인 필터 도구 사이에서 선택 상태를 공유한다.


### 거래 기간 달력

거래 필터 도구는 종류·기간·구성원·초기화 순서다. 구성원 선택은 내용에 맞는 폭을 사용한다. 기간 popover는 같은 달력에서 첫 클릭으로 시작일, 다음 클릭으로 종료일을 선택하며 역순이면 날짜 순으로 정렬한다. 같은 날짜 두 번은 하루, 월 제목 클릭은 해당 월의 첫날부터 마지막 날까지다. 선택 중인 시작일·종료일은 도구 안에서 확인하고 적용하면 기존 URL의 시작일 포함·종료일 다음 날 미포함 범위를 사용한다. 적용 전 닫으면 조회 조건을 바꾸지 않고, 기간 지우기는 다른 필터를 유지한다. 화면 크기 변경으로 선택 중인 범위를 초기화하지 않는다.

## 설정 B안과 탈퇴 (D-083)

설정은 공동 가계부·화면·내 계정 메뉴를 통해 한 영역씩 탐색한다. 768px 이상은 왼쪽 메뉴, 모바일은 동일 DOM의 상단 3열 메뉴다. 반복 구분선 대신 중립 표면·여백으로 묶고 초대 발급 내역은 접어서 시작한다. 선택 메뉴는 URL에 보존하며 숨긴 패널의 발급된 초대와 입력값을 잃지 않는다. 내 계정 하단에서 회원 탈퇴를 열고 가계부 전체 삭제는 공동 가계부 하단에 둔다. 탈퇴 확인은 가계부 없음/공유/마지막 구성원을 구분하고 현재 비밀번호·처리 내용 동의를 받는다. 오프라인·제출 중 중복 요청을 차단하며 412에서는 최신 구성을 다시 읽고 동의를 해제한다.

### 내 계정 편집 (D-084)

B안 내 계정에는 프로필 수정을 배치하고, 그 안의 ‘비밀번호 변경’ 버튼으로 별도 `/settings/password` 화면에 진입한다. 비밀번호 변경 화면에는 내 계정으로 돌아가기를 제공한다. 이름·이메일 입력 아래 현재 비밀번호와 저장 버튼을 두며, 이메일을 바꿀 때만 인증번호 전송/확인 영역을 보여준다. 인증번호 수신/완료 및 최종 저장을 구별한다. 비밀번호 변경은 기존 비밀번호·새 비밀번호·확인의 세 필드와 모든 기기 재로그인 안내를 제공한다. 오류·오프라인·412에서도 draft를 유지하며 화면 회전으로 form을 remount하지 않는다. 민감 입력을 localStorage/URL에 저장하지 않는다.

### 거래 입력 진입 경로 (D-088)

자산 상세의 `기록 추가`는 거래 기록 페이지 링크다. 입력 폼을 dialog 안에 중복 제공하지 않는다. URL의 `assetId`는 현재 활성 자산 목록으로 검증하고, 유효하지 않으면 기존 입력 기본값을 사용한다. 자산에서 시작한 기록은 저장 후 해당 자산으로 돌아가며 기존 목록 필터를 유지한다. 페이지의 `자산으로 돌아가기`와 브라우저 이동은 미저장 입력 확인을 공통으로 사용한다. 홈 달력의 명시 날짜와 최근 저장 날짜·결제 수단 기본값, 대표 결제·집계 제외·할부 동작은 유지한다.
