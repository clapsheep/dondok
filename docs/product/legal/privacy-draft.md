## 1. 처리 목적·항목·수집 방법

회원 입력, 같은 가계부 구성원의 입력 및 서비스 이용 과정에서 다음 정보를 처리합니다.

| 목적 | 항목 | 법적 근거·선택 여부 |
|---|---|---|
| 계정 생성·이메일 인증·로그인·복구 | 로그인 아이디, 이름(별명 가능), 이메일, 단방향 해시 비밀번호, 내부 사용자 ID, 인증·재설정 token digest와 발급·처리 시각 | 가입 필수 최소정보. 제15조 제1항 제1호 동의 방식의 문구를 별도 초안에 제안; 최종 근거 확정 필요 |
| 공동 가계부·원장·통계 제공 | 구성원 연결, 자산 종류·이름·명의·기준일 잔액·금융기관, 거래 금액·날짜·분류·당사자·작성자·수정자, 카드 구매·할부·결제 기록 | 기능 사용 시 입력하는 정보. 계약 이행 필요성과 동의 범위를 구분해 확정 |
| 회원이 선택해 입력한 설명 | 거래 메모·자산 메모·사용자 지정 이름 | 입력하지 않아도 해당 기본 기능 이용 가능. 민감정보나 타인의 불필요한 개인정보를 입력하지 않도록 안내 |
| 로그인 유지·접근 보호 | 세션 ID, 세션 시각, 요청 식별자, 보안 관련 요청 정보 | 계약 이행 및 보안에 필요한 범위. 실제 IP·User-Agent 등 저장 항목과 기간 확인 필요 |
| 동의 증거 | 내부 사용자 ID, 동의 종류·문서 버전·서버 기록 시각 | 향후 구현 예정. 보유기간·근거 확정 후 공개 |
| 문의·권리행사 처리 | 회신 연락처, 요청 내용, 필요한 최소 본인확인 정보 | 실제 접수 방법·보유기간 확정 필요 |

현재 가입 폼은 주민등록번호, 실명 증명서, 전화번호, 생년월일을 요구하지 않습니다. 금융기관 로그인 정보·실제 계좌 및 카드 번호를 요구하지 않습니다. 자유 입력란에는 건강정보 등 민감정보, 비밀번호·주민등록번호·카드번호를 기록하지 말아 주세요.

## 2. 보유기간과 파기

목적 달성, 보유기간 종료 또는 적법한 삭제 요청 시 관계 법령에 따라 지체 없이 파기합니다. 별도 법적 의무로 보존하는 경우에는 해당 항목·법령·기간을 구체적으로 안내하고 다른 용도로 사용하지 않습니다.

| 정보 | 게시 전 확정·검증할 기간 |
|---|---|
| 계정 정보 | 탈퇴 시 처리. 미인증 계정 자동 삭제 기한은 미확정 |
| 공동 기록·작성 콘텐츠·내부 식별자 | Q-063 해결 전 확정 불가. 가계부 삭제 또는 마지막 구성원 탈퇴 시 전체 가계부 삭제가 현재 정책 |
| 로그인 세션 | 미사용 30일 또는 생성 후 최대 90일 만료. 로그아웃·비밀번호 재설정·탈퇴 시 폐기. 만료 세션 정리 작업 대조 필요 |
| 인증·재설정 token | 사용 가능 시간은 각각 24시간·30분. 만료/사용 행의 실제 파기 주기는 별도 확정 |
| 서비스·보안·접속 로그 | 실제 수집 항목, 법적 근거와 삭제 주기 확정 필요 |
| 동의 증거·문의 기록 | 목적에 필요한 최소 기간과 삭제 작업 확정 필요 |
| 백업 | 기존 정책은 삭제 전 사본 최대 30일. 암호화·접근 제한·자동 만료·삭제 재적용을 검증한 뒤 문구 확정 |

전자 데이터는 복구하기 어렵도록 삭제하며 종이 자료를 취급한다면 분쇄 등으로 파기합니다. **표시명만 바꾼 공동 기록은 당연히 익명정보가 되는 것이 아닙니다.** 탈퇴 후 남는 데이터의 식별 가능성과 법적 근거를 확인해야 합니다.

## 3. 구성원 사이의 개인정보 공유

같은 가계부에서는 이름, 자산·거래·명의·작성 정보와 입력한 메모를 구성원이 함께 확인하고 편집합니다. 로그인 아이디·비밀번호·이메일은 구성원 공유 항목에 넣지 않습니다. 초대 확인 단계에서는 참여 전 상대방에게 구성원 이름이 보일 수 있습니다.

**[확정 필요: 수신자의 구체적 표시, 이용 목적, 항목, 보유기간, 거부 방법 및 영향과 수신자 추가 시 절차]**. 이 방침의 공개나 이용약관 동의만으로 별도 제공 동의가 필요한 처리를 대신하지 않습니다.

법령에 따른 제공은 적법한 요건을 확인하고 필요한 범위로 제한합니다. 공동 가계부 공유가 있으므로 ‘제3자 제공이 전혀 없다’고 표시하지 않습니다.

## 4. 처리위탁과 국외 이전

확인된 제품 결정은 인증·비밀번호 재설정 메일을 Resend SMTP로 발송하는 것입니다. 가입 시 이름·이메일과 인증 링크가 메일 본문에 포함됩니다.

| 항목 | 확인된 사실 및 확정할 내용 |
|---|---|
| 수탁 업무 | 인증·비밀번호 재설정 이메일 전송, 전달 결과 처리 |
| 수탁자·이전받는 자 | Resend. 계약 당사자의 정확한 법인명과 연락처는 실제 계약/DPA 대조 후 기입 |
| 이전 정보 | 이메일 주소, 표시명, 인증 또는 재설정 링크를 포함한 메일 내용, 발송·전달 정보 |
| 이전 시점·방법 | 이메일 전송 요청 시 SMTP 네트워크 전송. 운영 TLS 설정 확인 필요 |
| 국가 | Resend 문서상 주된 처리·저장은 미국. 계정 및 재수탁 서비스의 실제 국가 목록 대조 필요 |
| 보유기간 | 일반 요금제 메일·로그 30일, 백업 7일, 서비스 계약 종료 후 잔여 데이터 삭제 최대 90일이라는 업체 안내를 확인. 실제 적용 계약·개별 삭제 요청 처리와 대조 필요 |
| 이전 근거 | 제28조의8의 계약 이행에 필요한 위탁·보관 및 고지 요건 적용 여부 검토. 그 근거를 쓸 수 없다면 법정 항목을 알린 별도 동의 필요 |
| 거부·중지 | 공개 권리행사 연락처로 요청. 이메일 인증 필수 흐름의 실제 대체 가능성과 이용 제한 범위를 확정해 안내 |

운영자는 위탁계약으로 목적 외 처리 금지, 보호조치, 재위탁 관리와 삭제 의무 등을 정하고 이행을 확인해야 합니다. 현재 초안은 그 계약 이행이 검증됐다고 주장하지 않습니다.

Cloudflare DNS는 문서에 확인되나 프록시·분석 등 사용 여부는 추가 확인 대상입니다. 외부 로고 이미지·CDN·오류 수집 SDK·백업 보관업체도 출시 build의 네트워크와 운영 설정을 기준으로 누락 없이 조사합니다.

참고: [Resend 개인정보 처리 계약](https://resend.com/legal/dpa), [보관·저장 안내](https://resend.com/security/gdpr), [재수탁자](https://resend.com/legal/subprocessors).

## 5. 쿠키와 기기 저장소

로그인 유지를 위해 세션 쿠키를 사용합니다. 브라우저 설정에서 쿠키를 삭제하거나 차단할 수 있으나 로그인 유지가 제한될 수 있습니다. 테마와 최근 거래 입력 날짜·자산 선택 같은 입력 선호값을 기기 저장소에 보관합니다. 기기 간 동기화하지 않으며 사이트 데이터 삭제로 제거할 수 있습니다.

PWA는 정적 앱 파일을 기기에 보관합니다. 서비스 API 응답·금융 데이터의 영속 캐시와 오프라인 거래 전송 대기열은 제공하지 않습니다. 광고·행태 분석 및 메일 열람·링크 추적 유무는 실제 설정 확인 후 안내합니다.

## 6. 정보주체의 권리

회원은 개인정보 열람, 정정·삭제, 처리정지, 동의 철회를 요청할 수 있습니다. 앱 내 탈퇴 또는 **[권리행사 연락처]**로 요청해 주세요. 운영자는 최소한의 본인확인 후 법정 절차에 따라 처리하고, 제한이 있는 경우 구체적인 근거·사유와 이의제기 방법을 안내합니다. 대리인을 통한 요청도 적법한 대리권을 확인하여 처리합니다.

만 14세 이상만 가입할 수 있습니다. 만 14세 미만 아동의 개인정보가 잘못 수집된 사실을 알게 되면 법정대리인 등이 위 문의 경로로 알릴 수 있으며 확인 후 필요한 조치를 합니다. 표시명·이메일의 자가 수정 기능이 없다면 해당 기능이 있다고 안내하지 않고 실제 문의 경로를 제공합니다.

광고는 향후 도입 예정이며 이 초안으로 미래의 광고·개인화·추적에 대한 동의를 미리 받지 않습니다. 실제 도입 전에 처리 항목·SDK·제공 및 국외 이전 현황에 맞춰 방침과 필요한 동의 절차를 갱신합니다.

## 7. 보호조치와 구제

비밀번호 해시, 인증 token digest, HTTPS, 접근권한 제한, 세션 보호 등 실제 적용·검증한 조치를 안내합니다. 운영자 접근기록, 백업 암호화와 로그 정리는 운영 검증 후 포함합니다.

개인정보 관련 문의는 위 담당자에게 할 수 있습니다. 외부 구제가 필요한 경우 [개인정보 포털](https://www.privacy.go.kr/)에서 권리행사와 피해구제 안내를 확인할 수 있습니다.

## 8. 변경

처리방침 변경 시 변경 내용과 시행일을 게시하며 이전 버전도 확인할 수 있게 합니다. 별도 동의가 필요한 처리 변경은 방침 게시만으로 갈음하지 않습니다.
