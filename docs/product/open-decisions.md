# 돈독 미결정 질문 등록부

이 문서는 사용자 답변이 필요한 질문의 단일 원본이다. `권고`는 에이전트 의견일 뿐 결정이 아니며, 사용자가 답하기 전에는 구현 전제로 사용하지 않는다.

## 사용 규칙

- 상태: `OPEN` → `ANSWERED` 또는 명시적 `DEFERRED`
- 현재 작업의 결정 기한에 도달한 `OPEN` 질문만 사용자에게 묻는다.
- 한 번에 최대 3개를 묻고, 선택지·영향·권고를 함께 제시한다.
- 답변을 받으면 이 문서의 상태와 `docs/project-context.md`의 새 `D-*` 결정을 같은 변경에서 갱신한다.
- 질문과 무관한 안전하고 되돌릴 수 있는 구현 세부는 에이전트가 결정한다.

## 현재 우선순위

| Gate | 시점 | 질문 |
|---|---|---|
| G0 | 애플리케이션 scaffold 직전 | 없음 — Q-001 답변 완료 |

1. React SPA는 Q-001 답변으로 확정했다.
2. 개인 나가기는 Q-012 답변으로 제공하지 않기로 확정했다.
3. 이체에는 D-068의 고정 목적 5개를 제공하며 수입·지출 분류와 분리한다.
4. 실시간 화면 반영은 Q-029 답변으로 MVP 범위에서 제외했다. 기존 SSE·outbox 전제는 REST 재조회와 version 충돌 처리로 교체한다.

### Q-005 초대 방식과 기본 정책

- 상태: `ANSWERED`
- 답변: 초대 URL과 직접 입력 코드를 모두 제공하되 두 원문을 분리한다. 직접 입력 코드는 숫자 6자리이고 URL에는 추측하기 어려운 별도 고강도 token을 넣는다. 로그인한 사용자가 현재 구성원을 확인하고 `참여하기`를 누르면 기존 멤버의 추가 승인 없이 즉시 참여하고 홈으로 이동한다. 참여 후 초대 화면은 없으며 추가 구성원 초대와 발급 내역 관리는 가계부 설정에서 제공한다. 가계부는 사용자 지정 이름 없이 계정당 하나의 공동 공간으로 취급한다.
- 정책: 초대는 발급 시점부터 7일간 유효하고 한 번만 사용할 수 있다. 6자리 코드는 기존 초대와 중복되지 않게 DB unique와 충돌 재시도로 발급하고, 직접 코드 확인은 사용자별 rate limit을 적용한다. 이미 가계부가 있는 사용자는 수락할 수 없으며, invitation 행 잠금과 전역 user membership unique로 동시 수락을 직렬화한다.
- 답변일: 2026-07-11
- 출처: PM, Backend, Frontend, UX

### Q-006 거래의 경제활동 주체 범위

### Q-008 최초 잔액의 날짜 효력

### Q-009 자산 소유자 marker 변경과 과거 통계

### Q-011 카드 최초 음수 금액의 결제 예정 포함 여부

- 상태: `ANSWERED`
- 답변: 카드의 음수 기준일 잔액도 결제 예정에 포함한다. 잔액 기준일과 카드 마감·결제 설정으로 해당 명세와 결제 예정일을 계산하며, 계산된 결제일이 이미 지났다면 그 과거 예정일을 유지해 catch-up worker의 처리 대상으로 둔다.

- 연결 결정: 정확한 마감 월·말일 계산은 Q-016에서 확정한다.

### Q-036 삭제 가계부의 off-device 복구 내구성

- 상태: `OPEN`
- 결정 기한: weekly off-device 백업과 실제 disaster cutover 구현 전
- 배경: daily dump 안의 `audit_log`도 가계부와 함께 삭제되므로 삭제 전 backup만 복원하면 DB 자체에는 해당 가계부를 다시 제거할 근거가 없다. 로컬 restore drill의 선택 denylist는 코드 경로만 검증하며 실제 삭제 기록의 내구성을 만들지 않는다.
- 선택지 A: 삭제 확인 직후 DB 삭제보다 먼저 append-only 외부 tombstone을 동기적으로 내구화하고 이를 복구의 authoritative 삭제 목록으로 사용한다. 외부 기록이 불가능하면 삭제를 시작하지 않으며, 기록 뒤 로컬 트랜잭션이 실패해도 확인된 삭제 의도는 재시도·복구에서 최종 삭제로 수렴한다.
- 선택지 B: base backup과 연속 WAL/PITR를 Mac mini 밖에 보존하고 삭제가 포함된 복구 시점까지 replay한 결과만 서비스 승격 후보로 허용한다. 더 일반적인 시점 복구가 가능하지만 단일 개인 서버 운영 복잡도와 저장량이 커진다.
- 선택지 C: 외부에 마지막 삭제 완료 시각만 내구화하고 그 시각 이후 생성·복제된 backup만 복구 후보로 허용한다. 가장 단순하지만 삭제 직후 다음 backup 전 장애에는 사용할 수 있는 복구 지점이 없어진다.
- 권고: A. 현재 단일 Mac mini·낮은 사용자 규모에서 복구 목적을 삭제 재등장 방지로 좁히면서도 daily dump 구조를 유지할 수 있다.

### D-046 적금 자동이체 선택 설정

적금 등록·수정에서 자동이체는 선택 사항이다. 자동이체를 사용하지 않으면 `savingsSettings = null`로 저장하고 `savings_setting` 행을 만들지 않는다. 사용하면 출금 계좌와 달력일을 같은 설정으로 모두 입력해야 하며 부분 설정은 허용하지 않는다. 기존 설정이 있는 적금에서 자동이체를 끄면 설정 행을 삭제하되 적금 자산·거래·posting·잔액은 유지한다. 설정 자체로 자동 거래는 생성하지 않는다.

### D-047 사용자 선택 수입·지출 집계 제외

모든 사용자 수입·지출은 거래별로 집계 제외를 선택할 수 있다. 제외해도 자산 posting과 카드 구매·환불 원장은 그대로 반영하고 월간 달력과 통계 합계·분류·연간 흐름에서만 제외한다. 제외된 기록은 일별 원장과 상세에서 `집계 제외`로 식별하고 일반 거래 수정 또는 카드 구매 정정으로 다시 포함할 수 있다. 카드 환불은 원 구매의 선택을 기본으로 이어받되 환불 거래별로 바꿀 수 있고, 기존 거래와 필드를 보내지 않는 이전 클라이언트는 포함이 기본이다.
