요청 범위는 회원가입의 약관 동의와 앱스토어 출시 준비다. 사용자 최종 답변으로 대한민국 대상·개인 운영(미등록 사업자)·만 14세 이상 가입·Resend 이메일 발송·Cloudflare 사용·광고 향후 도입을 확인했다(D-085). 운영자 법적 표시·정확한 문의 주소·실제 처리 구성은 추가 확인 대상이다. 법률 준수나 심사 승인을 보증하는 문서가 아니다. 공개 전 개인정보 전문가의 검토와 실제 운영 설정 대조가 필요하다.

API·DB·backend·frontend·UX·QC에 영향이 있다. 원장 금액 계산은 변경하지 않는다. 가입은 기존 세션 query 흐름을 유지하며 가계부 cache 변경은 없다. 동의 여부를 브라우저 영속 저장소에 저장하지 않는다.

## 출시 전 해결할 사항

1. **탈퇴 후 공동 기록 보존과 Apple 삭제 기준의 충돌.** Apple은 공유된 사용자 작성 콘텐츠도 계정 삭제 대상이라고 설명한다. D-083은 메모·자산명·거래를 남기므로, 이름을 ‘탈퇴한 회원’으로 치환하는 것만으로 익명화 또는 심사 충족을 단정할 수 없다. 회원 ID, 금액·일자·메모 조합으로 재식별할 수도 있다. 사용자는 탈퇴자 데이터 전체 삭제 방향을 제안하고 영향 검토를 요청했다. 다른 구성원의 데이터·잔액 처리까지 확정된 것은 아니며 상세 영향은 별도 검토 문서에 기록한다. [Apple 공식 삭제 안내](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion)
2. **백업 정책과 구현의 일치.** 30일은 법정 면책 기간이 아니다. 제한 접근, 실제 암호화, 자동 만료, 복구 후 탈퇴 계정·삭제 콘텐츠 재등장 방지를 확인해야 한다. 현재 구조 검증용 복원 drill을 삭제 준수 검증으로 간주하지 않는다.
3. **계정·로그 보유기간.** 미인증 계정, 만료 token 행, 애플리케이션·reverse proxy·메일 로그, 동의 기록의 삭제 시점과 삭제 작업을 정해야 한다. token의 유효기간은 행의 실제 파기 시점이 아니다. 근거 없이 ‘법령상 5년 보관’을 넣지 않는다.
4. **위탁·국외 이전.** Resend 사용은 국내 서버 운영과 별개다. 발송 지역만으로 저장 국가를 판단하지 않는다. DNS 사용만으로 Cloudflare가 금융 데이터를 처리한다고 단정하지 않으며 프록시·분석 기능의 활성화 여부를 확인한다.
5. **공유 시점의 동의.** 미래의 모든 구성원을 포괄하는 가입 체크 하나로 끝내지 않는다. 초대 미리보기에서 보이는 이름, 초대 수락 후 보이는 기록, 기존 구성원에게 새로 추가되는 수신자의 범위를 각각 확인한다. 제17조 동의 방식이면 수신자 변경에 대한 안내·동의 설계가 필요하다.

## App Store 제출 대조

- 로그인 없이 열리는 HTTPS 개인정보처리방침을 App Store Connect와 앱 내부에 연결한다. 수집 항목·목적·보유/삭제·권리행사·외부 처리 내용을 일치시킨다. 심사 계정과 작동하는 backend를 제공한다. [심사 지침 5.1.1 및 제출 안내](https://developer.apple.com/app-store/review/guidelines/)
- Privacy Labels는 계정 연결 이메일·표시명·사용자 ID, 사용자가 입력한 금융 정보와 기타 콘텐츠를 실제 수집 목적에 맞춰 신고한다. SDK·서버 로그·외부 메일도 포함해 대조한다. 광고 추적이 없다면 ATT를 임의로 추가하지 않으며, ‘수집 없음’으로 신고하지 않는다. [App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/)
- 표시명은 공동 가계부에서 사용할 별명도 가능하게 안내한다. 생년월일·신분증·연락처·실제 계좌번호는 연령 확인 또는 약관 증거라는 이유만으로 추가 수집하지 않는다.
- 현재 저장소는 React PWA다. 약관 준비는 iOS 앱 제작·서명·제출과 별개다. 네이티브 패키지의 실제 기능, SDK, 개인정보 manifest와 필요 API 사유는 제출 build에서 검증한다. 단순 웹 포장이라면 4.2 심사도 별도로 확인한다.
- Google Play에도 출시한다면 앱 안의 삭제뿐 아니라 외부 웹 삭제 요청 경로와 Data safety 신고를 준비한다. [Google 사용자 데이터 정책](https://support.google.com/googleplay/android-developer/answer/10144311?hl=ko)
- 광고는 향후 도입 예정이므로 현재 가입에서 마케팅·맞춤 광고·추적 동의를 미리 받지 않는다. 광고 활성화 전에 실제 SDK와 수집·이전 항목, 연령별 정책에 맞춰 방침·필요 동의·스토어 신고를 갱신한다.

## 법령 근거

2026-09-11 시행 개인정보 보호법을 기준으로 열람했다. 계약에 필요한 개인정보 처리와 동의에 근거한 처리를 구분한다. 후자를 선택하면 목적·항목·보유기간·거부권 및 영향을 사전에 안내하고, 불필요한 수집을 가입 조건으로 만들지 않는다. 제3자 제공은 별도 요건을 확인한다. [제15~22조의2](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1006183947)

국외 위탁은 별도 동의만이 유일한 근거는 아니다. 계약 이행에 필요한 위탁·보관 예외를 적용하려면 그 필요성과 법정 고지 요건을 검토해야 한다. [제28조의8](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1020398611)

처리방침 공개는 수집·이용 동의와 구별하며, 개인정보 보호책임자·권리행사 방법 등 법정 사항을 포함한다. [제30조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1034292763)

이용약관은 중요한 내용을 설명하고 사본을 확인할 수 있게 하며, 사업자 책임의 부당한 면제와 불리한 전속관할 조항을 넣지 않는다. [약관의 규제에 관한 법률](https://www.law.go.kr/LSW/lsInfoP.do?ancYnChk=&chrClsCd=010202&efYd=20240209&lsiSeq=253655&urlMode=lsInfoP)
